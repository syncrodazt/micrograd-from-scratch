# Notes — how to work with me

บันทึกวิธีทำงานที่ได้ผล เพื่อไม่ต้องอธิบายซ้ำทุกเซสชัน

## ภาษา

- อธิบาย/คุยกัน: **ไทย**
- โค้ด, คอมเมนต์, commit message, README: **อังกฤษ** (recruiter อ่าน repo นี้)

## สิ่งที่ได้ผลจริง (ยืนยันจากวันที่ 2026-08-08)

- **ชี้จุดผิด + บอกประเภทของบั๊ก แล้วหยุด** — ไม่ต้องแก้ให้ วิธีนี้ทำให้แก้เองได้ทั้ง 4 บั๊กในวันเดียว
- **วัดของจริงแทนการเดา** — รันโค้ดจริงแล้วเอาตัวเลขมาแสดง (80 ns, 524,287 calls, `is → True`)
  น่าเชื่อถือกว่าคำอธิบายลอยๆ มาก
- **ให้เทสต์ที่ต้องทำให้ผ่าน** แทนการให้โค้ด (`assert len(nodes) == 5`)
- **ให้ทำนายก่อนรัน** แล้วค่อยเทียบผล — จับได้ว่าตรงไหนที่ mental model ไม่ตรงความจริง
- **เชื่อมกับ control theory** — recursion ≈ induction, backprop ≈ adjoint equation,
  `origin/main` ≈ state estimate ที่อัปเดตเฉพาะตอน sampling
- ตอบสั้นเมื่อขอสั้น — บางจังหวะอยากได้แค่ยืนยันว่าคิดถูก ไม่ใช่บทความ

## สิ่งที่ห้ามทำ

- ห้ามเขียนโค้ดหลักให้ (`Value`, dunder methods, `_backward`, topo sort, `backward()`, `nn.py`, makemore)
- ห้ามแก้บั๊กให้ แม้จะเป็นตัวอักษรเดียว
- ห้ามวาง reference implementation หรือ pseudocode ที่จริงๆ แล้วคือคำตอบ
- ห้ามเขียนเนื้อความ README — นั่นคือตัวชิ้นงานจริง
- ห้ามลง GitHub Copilot ในเดือนนี้ · ห้ามกดปุ่ม `✦ Generate` ในรีโปนี้

## จังหวะที่สังเกตได้

- ชอบเข้าใจ *ทำไม* ก่อนลงมือ — ถามว่า "ทำไมต้องแก้เรื่องเดินซ้ำ" แทนที่จะแก้แล้วผ่านไป
  ให้เหตุผลเชิงกลไกเสมอ อย่าบอกแค่ว่าต้องทำ
- ยอมรับได้กับการถูกบอกว่าคิดผิด ถ้ามีหลักฐาน
- ท้อได้เวลาเทียบตัวเองกับวิดีโอ — ให้เตือนว่าวิดีโอคือการ *แสดง* ไม่ใช่การ *เรียน*
