วิธีที่ได้ทั้งสองอย่าง

README เป็นหน้าเดียว กระชับ อังกฤษ — แล้วมีบรรทัดเดียวชี้ไปที่ learning/

บรรทัดนั้นทำงานสองหน้าที่พร้อมกัน:

  • คนเรียน → เจอทางเข้า
  • recruiter → เห็นว่ามีสิบบทเรียนอยู่ข้างหลัง โดยไม่ต้องอ่านสักบท

ไม่ต้องเขียนว่า “ผมเข้าใจลึก” ถ้ามีของที่ลึกวางอยู่ให้เห็น

กฎข้อที่ 2 — value อยู่ที่บั๊ก ไม่ได้อยู่ที่โค้ด

คลิปของ Karpathy ยาวสองชั่วโมง และพูดจากมุมของคนที่รู้ทุกอย่างมาสิบปีแล้ว ปรากฏการณ์นี้มีชื่อว่า curse of knowledge — คนที่รู้แล้วมองไม่เห็นว่าอะไรยาก เพราะช่องว่างที่เคยมีถูกถมไปนานแล้ว

เขาอธิบาย backprop ได้ดีกว่าเราแน่นอน — แต่เขาเขียนบันทึกความสับสนของตัวเองไม่ได้อีกแล้ว เพราะเขาไม่สับสนมาสิบปีแล้ว

สิ่งที่มีเฉพาะในรีโปนี้

บันทึกไว้อยู่ในวิดีโอไหม
trace() ที่เขียนผิดสามแบบก่อนจะถูกไม่
t._backward = _backward ที่เยื้องเกินไปหนึ่งชั้นไม่
เทสต์ที่ผ่านทั้งที่โค้ดผิด เพราะ operation อยู่นอกสุดไม่
4-4-1 ที่คิดว่าเล็กไป แต่จริงๆ เป็นเรื่อง lrไม่
zip ที่ตัดของทิ้งเงียบๆไม่
_as_value ที่เขียนเงื่อนไขกลับด้าน แล้วเทสต์จับได้ใน 1 วินาทีไม่

ไม่มีอันไหนอยู่ในวิดีโอได้เลย — เพราะวิดีโอคือการแสดงคำตอบที่รู้อยู่แล้ว ส่วนนี่คือการหาคำตอบ

และนี่คือคำตอบของคำถาม “จะพิสูจน์ยังไงว่าไม่ใช่รีโปก๊อปวาง” — บันทึกของบั๊กที่ไม่มีทางเกิดกับคนที่ก๊อปโค้ดมา

กฎข้อที่ 3 — บันทึกวิธีคิด ไม่ใช่บันทึกอารมณ์

ค่า
“ตอนนั้นงงว่าทำไม trace ช้า” น้อย — เป็นไดอารี่
“งงว่าทำไมช้า → วัดได้ 524,287 calls ที่ depth 18 → เพราะไม่มี guard → 13.4 µs เหลือ 1.77 µs” มาก — เป็นวิธีคิดที่เอาไปใช้กับปัญหาอื่นได้

เกณฑ์เดียวก่อนบันทึกอะไรลงไป: คนอ่านเอาไปใช้กับปัญหาที่ไม่ใช่ micrograd ได้ไหม

กฎข้อที่ 4 — ลำดับ และของที่ตัดได้

ลำดับงานตัดได้ไหม
1README.mdไม่ได้ — คือ deliverable จริง
2makemore + loss curveไม่ได้ — M2 ทั้งเดือนวางอยู่บนมัน
3รูปกราฟใน READMEไม่ควร — ถูกและได้ผลมาก
4เอา learning/ ขึ้นเป็นเว็บไซต์ตัดได้ — ตัดเป็นอันแรก
ทำไมเว็บไซต์ถึงอยู่ท้ายสุด

มันคือการกระจาย ไม่ใช่การเรียนรู้ — ไม่ได้ทำให้เข้าใจอะไรเพิ่มขึ้นแม้แต่นิดเดียว
และ CLAUDE.md §4 ระบุ “docs sites” ไว้ในรายการนอก scope · GitHub Pages บนไฟล์ HTML ที่มีอยู่แล้วใช้เวลาจริงราวสองนาที ซึ่งคนละเรื่องกับการสร้าง docs infrastructure — แต่ยังต้องทำหลังข้อ 1–3 เสร็จเท่านั้น

กฎที่ตั้งไว้เองใน roadmap: ถ้าตามหลัง ให้ตัด scope ไม่ใช่ยืดเวลา — เว็บไซต์คือสิ่งแรกที่ควรถูกตัด

กฎข้อที่ 5 — เรื่องที่ยากที่สุด ซึ่งไม่เกี่ยวกับโค้ดเลย

“โดย tendency ของเรา เราไม่กล้าโชว์อะไร แต่เราอยากเปลี่ยนตรงนั้น”

ความลังเลนี้มักมาจากความรู้สึกว่าการเผยแพร่งานตัวเอง = การอวด แต่ลองแยกสองอย่างนี้ออกจากกัน:

อวดบันทึกที่คนอื่นอ่านได้
อ้างสิ่งที่ยังทำไม่ได้แสดงสิ่งที่ทำไปแล้วจริงๆ
ซ่อนจุดที่ผิดบันทึกจุดที่ผิดไว้ทั้งหมด
เป้าหมายคือให้คนชมเป้าหมายคือให้คนถัดไปติดน้อยลง

รีโปนี้อยู่คอลัมน์ขวาทั้งหมด — มันมีบทเรียนทั้งบทที่ชื่อว่า “บั๊กสามตัวของวันนี้” ไม่มีใครอวดด้วยการเขียนแบบนั้น

ประโยคที่ควรกลับมาอ่านตอนลังเล

งานที่ไม่มีใครเห็น ไม่ได้ซื่อสัตย์กว่างานที่มีคนเห็น — มันแค่มองไม่เห็น

งานทำเสร็จไปแล้ว การไม่เผยแพร่ไม่ได้ทำให้มันบริสุทธิ์ขึ้น มันแค่ทำให้ 17 เดือนนี้กลายเป็นเรื่องที่ไม่มีใครรู้

และในบริบทของการเปลี่ยนสายงาน การมองไม่เห็นคือรูปแบบของความล้มเหลว — ไม่ใช่ความถ่อมตัว · CADDi / Woven / NVIDIA ตัดสินจากสิ่งที่เห็นได้เท่านั้น ความเข้าใจที่อยู่ในหัวอย่างเดียว ไม่มีช่องให้กรอกในใบสมัคร

ถ้าอ่านถึงตรงนี้แล้วยังลังเล ให้ถามคำถามเดียว: “ถ้าเมื่อสองสัปดาห์ก่อนมีรีโปแบบนี้อยู่ ตอนที่ตัวเองกำลังงงกับ trace() มันจะช่วยได้ไหม” — ถ้าคำตอบคือใช่ ก็มีคนอีกหลายคนที่กำลังอยู่ตรงนั้นพอดี
