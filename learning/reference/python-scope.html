global · nonlocal · closure

สามคำที่คนสับสนกันมากที่สุดใน Python — เพราะจริงๆ แล้วมันไม่ใช่ของประเภทเดียวกัน หน้านี้เป็นเอกสารอ้างอิง กลับมาเปิดซ้ำได้เรื่อยๆ

2026-08-09 · ใช้กับ trace() วันนี้ และ _backward พรุ่งนี้

เคลียร์ประเภทก่อน

ความสับสนเกือบทั้งหมดมาจากการเอาสามอย่างนี้มาวางเทียบกันทั้งที่มันคนละชนิด:

เป็นอะไรทำหน้าที่อะไร
closure กลไก ของภาษา ฟังก์ชันข้างในจำตัวแปรของฟังก์ชันข้างนอกได้ — เกิดขึ้นเองอัตโนมัติ
nonlocal คำสั่ง (keyword) “ตอนฉัน assign ทับชื่อนี้ ให้ไปแก้ของฟังก์ชันแม่ อย่าสร้างตัวใหม่”
global คำสั่ง (keyword) เหมือนกัน แต่ชี้ไปที่ระดับไฟล์แทน
ประโยคเดียวที่ต้องจำ

closure เกิดขึ้นแม้ไม่ใช้ nonlocal เลย — ถ้าแค่อ่านค่า หรือแค่ .append() ก็เป็น closure อยู่แล้ว nonlocal จำเป็นเฉพาะตอนเขียนทับชื่อ

ลำดับการค้นหาชื่อ: LEGB

Python หาชื่อตัวแปรตามลำดับนี้ และหยุดทันทีที่เจอ:

L  Local        ในฟังก์ชันตัวเอง
E  Enclosing    ฟังก์ชันแม่ที่ครอบอยู่        ← closure อยู่ตรงนี้
G  Global       ระดับไฟล์ (module)
B  Built-in     len, print, sum ...

LEGB ใช้กับการ อ่าน เท่านั้น — การ เขียนทับ จะสร้างตัวใหม่ที่ L เสมอ เว้นแต่จะประกาศ nonlocal (ไปที่ E) หรือ global (ไปที่ G)

คุณสมบัติที่ทำให้ closure เป็น closure

ตัวแปร local ปกติ ตายทันทีที่ฟังก์ชันจบ แต่ตัวแปรที่ถูก closure จับไว้ อยู่ต่อ: 

def make_counter():
    n = 0
    def bump():
        nonlocal n
        n += 1
        return n
    return bump          # ← make_counter จบตรงนี้ n ควรจะตายแล้ว

c1 = make_counter()
c2 = make_counter()

print(c1(), c1(), c1())   # 1 2 3
print(c2())               # 1   ← ไม่ใช่ 4
  1. make_counter จบไปแล้ว แต่ c1() ยังใช้ n ได้ — n ไม่ตายเพราะ bump ยังถือกล่องมันอยู่
  2. c1 กับ c2 มี n คนละตัว

“ไม่ตาย” ≠ “เป็น global”

นี่คือจุดที่คนพลาดมากที่สุด — ทั้ง global และ closure ต่างก็ “ไม่ตาย” แต่ด้วยเหตุผลคนละอย่าง และผลที่ตามมาต่างกันสิ้นเชิง 

# ---- GLOBAL ----                  # ---- CLOSURE ----
count = 0                           def make_bump():
def bump_global():                      count = 0
    global count                        def bump():
    count += 1                              nonlocal count
    return count                            count += 1
                                            return count
                                        return bump

ต่างข้อ 1 — จำนวนชุด

=== GLOBAL: สองคนใช้ ตัวเดียวกัน ===
A: 1 2 3
B: 4                    ← B อยากเริ่มใหม่ แต่ได้ต่อจาก A

=== CLOSURE: สองคน ได้คนละตัว ===
a: 1 2 3
b: 1                    ← b เริ่มที่ 1 ไม่เกี่ยวกับ a
a ต่อ: 4                ← a ยังนับของตัวเองต่อ

global มีชุดเดียวตลอดกาล · closure ได้ชุดใหม่ทุกครั้งที่เรียกฟังก์ชันแม่

ต่างข้อ 2 — เข้าถึงได้จากไหน

'count' อยู่ใน globals() ไหม : True
ค่าของมันคือ                  : 4       ← ของ global เท่านั้น
a เก็บ count ไว้ที่            : 4
b เก็บ count ไว้ที่            : 1

count ของ a และของ b ไม่ได้อยู่ใน globals() เลย และไม่ได้อยู่ใน namespace ไหนทั้งนั้น — เรียกถึงมันด้วยชื่อไม่ได้จากที่ใดในโปรแกรม มันมีอยู่แค่ในกล่อง (cell) ที่ a ถืออยู่ ต้องงัดผ่าน a.__closure__[0].cell_contents ถึงจะแอบดูได้

ต่างข้อ 3 — ใครก็พัง global ได้

count = 999                        ← ใครสักคนเขียนบรรทัดนี้
หลังจากนั้น bump_global()  -> 1000  💥
แต่ closure ของ a ยังเป็น  -> 5     ✅ ไม่มีใครแตะได้

อุปมาที่ใช้ได้

global ตู้เก็บของกลางของทั้งอาคาร — มีตู้เดียว ใครก็เปิดได้ ใครก็รื้อได้
closure ล็อกเกอร์ส่วนตัวใบใหม่ ที่ออกให้ทุกครั้งที่เรียกฟังก์ชันแม่ — มีแค่ฟังก์ชันข้างในที่ถือกุญแจ

เหตุผลที่ “ไม่ตาย” ต่างกัน:

  • global ไม่ตายเพราะมันอยู่ใน namespace ของไฟล์ตลอดอายุโปรแกรม
  • closure ไม่ตายเพราะยังมีคนถือกุญแจอยู่ — พอไม่มีใครถือ a แล้ว กล่องนั้นก็ถูกเก็บกวาดไป

ตารางสรุป

globalnonlocal (closure)
ชี้ไปที่ scope ไหนระดับไฟล์ฟังก์ชันแม่ที่ครอบอยู่
มีกี่ชุด1 ชุดตลอดกาล1 ชุดต่อการเรียกฟังก์ชันแม่ 1 ครั้ง
เรียกด้วยชื่อจากข้างนอก✅ ได้❌ ไม่ได้เลย
คนอื่นเขียนทับได้✅ ได้ (อันตราย)❌ ไม่ได้
ตายเมื่อไหร่จบโปรแกรมเมื่อไม่มีใครถือฟังก์ชันข้างในแล้ว
สร้างชื่อใหม่ได้ไหม✅ ได้❌ ต้องมีอยู่ก่อน

ข้อสุดท้ายทดสอบแล้ว:

global brand_new  → สร้างขึ้นมาเฉยๆ ได้ (brand_new = 42)
nonlocal nope     → SyntaxError: no binding for nonlocal 'nope' found

เมื่อไหร่ต้องใส่ keyword

def outer():
    bucket = []
    total  = [0]

    def inner():
        len(bucket)         # อ่านเฉยๆ         → ไม่ต้อง
        bucket.append("x")  # แก้ของในกล่อง    → ไม่ต้อง
        total[0] += 1       # แก้ของในกล่อง    → ไม่ต้อง (แม้จะมี +=)
        # bucket = []       # ชี้ไปกล่องใหม่   → ต้อง nonlocal
เส้นแบ่งที่แท้จริง

ไม่ใช่ += — แต่คือ “ชื่อนั้นยังชี้ไปที่เดิมไหม”
total[0] += 1 ไม่ต้องใช้ nonlocal เพราะชื่อ total ยังชี้ list ก้อนเดิม แค่ของข้างในเปลี่ยน

ส่องดูของจริง

f.__code__.co_freevars   → ('nodes',)      ชื่อที่ f ใช้แต่ไม่ได้นิยามเอง
f.__closure__            → (<cell at 0x...>,)   กล่องที่ f แบกติดตัวไป
f.__closure__[0].cell_contents  → []       ข้างในกล่อง

ฟังก์ชันธรรมดา __closure__ → None

Free variable = ชื่อที่ฟังก์ชันใช้แต่ไม่ได้นิยามเอง และไม่ได้รับมาเป็น argument ฟังก์ชันที่มีตัวแปรลอยแบบนี้เรียกว่า “เปิด” — Python “ปิด” (close over) มันให้ จึงได้ชื่อว่า closure

ทำไม trace() ต้องใช้ closure ไม่ใช่ global

def trace(root):
    nodes = set()          # ← ล็อกเกอร์ใบใหม่ทุกครั้งที่เรียก trace
    def f(node):
        nodes.add(node)    # ← ไม่ต้อง nonlocal เพราะ add ไม่ได้เปลี่ยนกล่อง
    ...

ถ้าใช้ global แทน:

nodes = set()              # ตัวเดียวทั้งโปรแกรม
def trace(root):
    global nodes
    ...

→ เรียก trace(d) แล้วเรียก trace(z) ต่อ จะได้ node ของ d ปนมาด้วย ต้องมานั่งล้างเองทุกครั้ง และถ้าลืมล้างจะเจอบั๊กที่หาไม่เจอ

Payoff: _backward

_backward ของแต่ละ operation จะเป็น closure ที่ แบก self, other และ out ติดตัวไป หลังจาก __add__ return ไปแล้ว

พอถึงเวลา backward — __add__ จบไปนานแล้ว แต่ closure ยังจำได้ว่าตัวเองเกิดจากใคร นี่คือกลไกที่ทำให้ backward pass เป็นไปได้ ถ้าไม่มี closure จะต้องเก็บข้อมูลพวกนี้ไว้เองด้วยมือทุก node

และเพราะแต่ละ node ได้ล็อกเกอร์คนละใบ node ที่ต่างกันจึงจำ self/other ของตัวเองได้โดยไม่ปนกัน — ซึ่งถ้าใช้ global จะทำไม่ได้เลย
