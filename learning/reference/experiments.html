ระดับ 1 — เซลล์เดียว ประมาณ 5 นาที

1 · บรรทัดว่างหนึ่งบรรทัดใน names.txt

มันเปลี่ยนตาราง 27×27 ไปกี่ช่อง และเปลี่ยนอะไรตอน sample?

  • สร้างตารางนับสองอัน — อันหนึ่งจากข้อมูลปกติ อีกอันเติมชื่อว่าง "" เข้าไป 1 ตัว
  • เทียบทีละช่อง แล้วนับว่าต่างกันกี่ช่อง
  • คำนวณ p(. | .) ของตารางที่ปนเปื้อน แล้วแปลงเป็น “ต่อการ sample 1 ล้านชื่อ”
▸ ตัวเลขที่ต้องเจอ
ช่อง (0,0) = (. , .)   0 -> 1
ช่องอื่น เปลี่ยน 0 ช่อง

p( . | . ) = 1/32,034 = 0.00003122
-> sample 1,000,000 ชื่อ ได้ชื่อว่างราว 31 ชื่อ

NLL แทบไม่ขยับ เทสต์ทั่วไปผ่านหมด — แต่โมเดลเชื่อไปแล้วว่า ชื่อที่ไม่มีตัวอักษรเลยเป็นไปได้

2 · คูณ probability ซ้ำๆ จนกลายเป็นศูนย์

float64 ทนการคูณความน่าจะเป็นได้กี่ตัวก่อนจะเป็น 0.0 พอดี?

  • หยิบ p ของ bigram ตัวหนึ่ง แล้วคูณสะสมไปเรื่อยๆ นับจำนวนครั้งจนได้ 0.0 เป๊ะ
  • คำนวณ P(ชื่อ) ของชื่อสั้นและชื่อยาว เทียบกัน
  • รวม log p ของทั้ง corpus แล้วลอง exp กลับ
▸ ตัวเลขที่ต้องเจอ
ava          1.656744e-04
emma         3.478214e-06
olivia       2.483135e-08
alexandria   6.311320e-12

คูณซ้ำ -> ได้ 0.0 พอดี หลังจาก 408 ตัว
corpus มี 228,146 ตัว

log-likelihood ทั้ง corpus = -559,873.6
exp ของค่านั้น              = 0.0   (underflow)
NLL ต่อ bigram              = 2.4540

log ไม่ใช่ความสะดวก — ถ้าไม่ใช้ ตัวเลขเป็นศูนย์ แล้ว gradient เป็นศูนย์หมด เทรนไม่ได้เลย

3 · zip ที่ไม่มี strict=True

ส่ง input มา 2 ตัวให้ neuron ที่รอ 3 ตัว — จะรู้ตัวไหม?

  • เอา Neuron(3) มาเรียกด้วย list ที่มีแค่ 2 ตัว
  • ดูว่าได้อะไรกลับมา แล้วลองใส่ strict=True เทียบ
  • ลองทำแบบเดียวกันใน MLP ลึกๆ แล้วถามตัวเองว่าจะไล่เจอยังไง
▸ ตัวเลขที่ต้องเจอ
n = Neuron(3)
n([1.0, 2.0])
-> Value(data = 0.9689875274388016)      ไม่มี error เลย

zip(self.ws, xs, strict=True)
-> ValueError: zip() argument 2 is shorter than argument 1

4 · <S> กับ <E> แยกกัน แทนที่จะยุบเป็น .

NLL เปลี่ยนไหม แล้วมีอะไรพังตอน normalize?

  • สร้างตาราง 28×28 โดยใช้สองโทเคนแยก แล้วคำนวณ NLL เทียบกับแบบ 27×27
  • ลองหารทุกแถวด้วยผลรวมของแถว — สังเกตว่าเกิดอะไรขึ้น
  • นับว่าช่องที่เป็นศูนย์เพิ่มมากี่ช่อง
▸ ตัวเลขที่ต้องเจอ
NLL แบบ .        = 2.454014
NLL แบบ <S>/<E>  = 2.454014      เท่ากันเป๊ะ

แถว <E> -> sum = 0  ->  0/0
คอลัมน์ <S> -> ศูนย์ทั้งคอลัมน์
ช่องตายเพิ่มมา 55 ช่อง

Python ล้วนโยน ZeroDivisionError · torch ให้ nan เงียบๆ แล้วแพร่ไปทั่ว tensor · ถ้าเทรน network บน 28 โทเคน แถว <E> ไม่เคยได้ gradient เลย ส่วนคอลัมน์ <S> ถูกกดลงหา −∞ ไม่มีวันหยุด

5 · ลบ reversed() ออกจาก topo() ⭐

parameter กี่ตัวจาก 41 ที่ได้ gradient ถูก และมี error กี่ตัว?

  • สร้าง MLP(3, [4, 4, 1]) forward หนึ่งครั้ง เก็บ gradient ที่ถูกต้องไว้
  • ล้าง gradient ทั้งกราฟ แล้วเรียก _backward() ตามลำดับกลับด้าน
  • นับว่ากี่ตัวที่ grad == 0.0 พอดี และกี่ตัวที่ตรงกับของจริง
▸ ตัวเลขที่ต้องเจอ
parameter ทั้งหมด               : 41
grad = 0.0 พอดี (ไม่ได้เรียนเลย) : 41
ตรงกับของจริง                   :  0

ถูก -0.035150   |   ไม่มี reversed +0.000000
ถูก +0.070301   |   ไม่มี reversed +0.000000

node ทั้งกราฟ = 126 | ไม่มี error ขึ้นเลยสักตัว

41 จาก 41 ไม่ใช่ “ส่วนใหญ่” แต่ทั้งหมด — training loop จะรันครบ 100 รอบ อัปเดตด้วยศูนย์ทุกครั้ง แล้วรายงาน loss ที่ไม่ขยับ

6 · ตาราง 2 มิติของเหรียญ

บวกตามแกนไหนได้ 1 และบวกตามแกนไหนไม่ได้อะไรเลย?

  • โยน 10 ครั้ง · สร้างตารางที่แถว = จำนวนหัว 0–10 คอลัมน์ = p หลายค่า
  • บวกตามคอลัมน์ (ตรึง p) และบวกตามแถว (ตรึงข้อมูล)
  • หาช่องที่ k = 7 ตัดกับ p = 0.5
▸ ตัวเลขที่ต้องเจอ
  หัว |  p=0.1   p=0.3   p=0.5   p=0.7   p=0.9
    3 | 0.0574  0.2668  0.1172  0.0090  0.0000
    5 | 0.0015  0.1029  0.2461  0.1029  0.0015
    7 | 0.0000  0.0090  0.1172  0.2668  0.0574  *
  ----+----------------------------------------
 รวม | 1.0000  1.0000  1.0000  1.0000  1.0000

แถวที่ 7 รวม = 0.4504    ไม่ได้แปลว่าอะไร

ลงคอลัมน์ = probability (รวมได้ 1) · ข้ามแถว = likelihood (ไม่ได้ 1)
ช่อง * คือ 0.1172 — ปรากฏในทั้งสองแบบ เพราะมันคือช่องเดียว

7 · C(10,7) ขยับจุดสูงสุดไหม

ตัดสัมประสิทธิ์ทวินามทิ้ง แล้ว argmax เปลี่ยนไปไหม?

  • คำนวณ likelihood ของ “หัว 7 จาก 10” ตลอดช่วง p — ทั้งแบบมีและไม่มี C(10,7)
  • หาตำแหน่งสูงสุดของทั้งสองเส้น
  • หารความสูงของยอดทั้งสองเส้น
▸ ตัวเลขที่ต้องเจอ
p        มี C(10,7)     ไม่มี C(10,7)
0.50     0.117188      0.000977
0.70     0.266828      0.002224    <- สูงสุดทั้งคู่
0.80     0.201327      0.001678

จุดสูงสุด: p = 0.7 ทั้งสองแบบ
สูงต่างกัน 120.0 เท่า  (= C(10,7) พอดี)

หลักการเดียวกับ log — ค่าคงที่เทียบกับพารามิเตอร์ ยกกราฟทั้งเส้นโดยไม่ย้ายยอด · และนี่คือเหตุผลที่ multinomial coefficient หายไปจาก loss ของ makemore

8 · ลืม zero_grad — ตื้นกับลึกไม่เหมือนกัน

รอบที่ 100 gradient เป็นกี่เท่าของรอบแรก — และคำตอบเดียวใช้ได้กับทุก parameter จริงไหม?

  • เรียก backward() ซ้ำบนกราฟเดิม โดยไม่ล้างและไม่อัปเดตอะไรเลย
  • ดู สองตัว: parameter ของชั้นสุดท้าย (ติด root) และของชั้นแรก (ลึกสุด)
  • แยกทดลองอีกอัน: training loop จริงที่ต่างกันแค่มี/ไม่มี zero_grad
▸ ตัวเลขที่ต้องเจอ
ลูกโดยตรงของ root  (L = a * 2.0)
   รอบ   1 -> 2.0     (x1)
   รอบ 100 -> 200.0   (x100)        เชิงเส้น

ใน MLP จริง
   รอบ |  ชั้นสุดท้าย        |  ชั้นแรก
      1 |  +0.910922 (x1)    |  +0.000483 (x1)
      3 | +19.129353 (x21)   |  +0.079744 (x165)
    100 | +8.4e7   (x9.2e7)  |  +2.4e16  (x5e19)

training loop จริง (lr = 0.05)
   step |  มี zero_grad          |  ลืม
    100 | loss 0.00030  g -0.0007 | loss 0.04000  g +0.9169

เชิงเส้นเฉพาะตอนที่ parameter เป็นลูกโดยตรงของ root — มี node ตัวกลางเมื่อไหร่ ตัวกลางก็สะสมด้วย กลายเป็นทบต้น
ใน loop จริงมันไม่ระเบิด แต่กระเด็นไปติดขอบ tanh แล้วค้างที่ 0.04000 เป๊ะทุก step — ดูเหมือนลู่เข้า ทั้งที่ตายแล้ว

9 · เป้าที่ 1.0 เทียบกับ 0.9

ตั้งเป้าที่ tanh ไปไม่ถึง แล้ว loss ต่างกันกี่เท่าหลัง 400 รอบ?

  • เทรน MLP(3, [4, 4, 1]) สองรอบด้วย seed เดียวกัน ต่างกันแค่เป้าหมาย ±1.0 กับ ±0.9
  • บันทึก loss และผลรวม |grad| ทุก step
  • ดู output จริงตอนจบ ว่าห่างจากเป้าแค่ไหน
▸ ตัวเลขที่ต้องเจอ
รอบ |  เป้า 1.0                |  เป้า 0.9
    |  loss       |grad|       |  loss       |grad|
 50 |  0.014804   0.336383     |  0.001227   0.147666
400 |  0.001368   0.033090     |  0.000026   0.008647

output เป้า 1.0 : 0.98140  -0.98459  -0.97796  0.98271
output เป้า 0.9 : 0.90001  -0.90330  -0.89614  0.89970

loss ต่างกัน 53 เท่า · เป้า 0.9 ตรงถึงทศนิยม 4 ตำแหน่ง ส่วนเป้า 1.0 ยังห่าง 0.019
บทเรียนที่ใหญ่กว่า: gradient เล็ก แปลได้สองอย่างที่ตรงข้ามกัน — ถึงจุดต่ำสุดแล้ว หรืออยู่ในเขตแบน · แยกจาก gradient อย่างเดียวไม่ได้ ต้องดู loss ประกอบ

10 · ความถี่ที่นับได้ ชนะทุกอย่างจริงไหม ⭐

สุ่มขยับการแจกแจง 200,000 ครั้ง จะเจอที่ NLL ต่ำกว่ากี่ครั้ง?

  • หยิบแถวเดียวของตารางนับ เช่นแถวของ a — 27 ช่อง
  • คำนวณ NLL ที่ความถี่ที่นับได้
  • รบกวนด้วย noise เล็กๆ แล้ว normalize ใหม่ · ทำซ้ำหลายแสนครั้ง นับว่าเจอที่ดีกว่ากี่ครั้ง
▸ ตัวเลขที่ต้องเจอ

NLL ที่ความถี่ที่นับได้        = 2.682714
สุ่มขยับ 200,000 ครั้ง -> ดีกว่า 0 ครั้ง

11 · ป้อน index ตรงๆ เทียบกับ one-hot

โมเดลที่รับตัวเลข 0–26 ตรงๆ ทำได้ดีแค่ไหน?

  • เทรนโมเดลที่รับ index เป็นเลขตัวเดียว — พารามิเตอร์แค่ 27 ตัว (และลองแบบมี bias อีกรอบ)
  • เทียบกับ one-hot 27×27 และกับการทายมั่ว 1/27
  • สังเกตแถวของ . เป็นพิเศษ — มัน index เท่าไหร่ แล้วผลคูณออกมาเป็นอะไร
  • ระวัง: learning rate สูงไปนิดเดียว optimizer ระเบิดแล้วได้ NLL หลักร้อย · พิมพ์ loss ทุกร้อย step เพื่อยืนยันว่ามันลง
▸ ตัวเลขที่ต้องเจอ
D  ทายมั่ว 1/27        (0 param)   -> NLL = 3.2958
B  index ตรงๆ         (27 param)  -> NLL = 2.8740
C  index + bias       (54 param)  -> NLL = 2.7628
A  one-hot           (729 param)  -> NLL = 2.4540

'.' มี index = 0 → 0 × w = 0 ทุกช่อง → softmax ให้ 1/27 เท่ากันหมด · โมเดลถูกบังคับให้ทายมั่วว่าชื่อขึ้นต้นด้วยอะไร และไม่มีค่า w ไหนแก้ได้

นี่คือรูปธรรมของ “index ยัดโครงสร้างปลอม” — มันไม่ได้แค่บอกว่า e มากกว่า a ห้าเท่า แต่ยังบอกว่า . คือศูนย์ คือไม่มีอะไรเลย

13 · _backward สร้างวงกลม

Value ถูกปล่อยทันทีที่ไม่มีใครถือมันแล้วจริงไหม?

  • ดูว่า closure ของ _backward จับตัวแปรอะไรไว้บ้าง — มันจับ node ที่มันแปะอยู่ด้วยหรือเปล่า
  • สร้างกราฟเล็กๆ · ทำ weakref ไปที่ root · ลบ reference ทั้งหมด
  • เช็คว่า root ตายทันทีไหม แล้วค่อยเรียก cycle collector แล้วเช็คใหม่
▸ ตัวเลขที่ต้องเจอ
sizeof(_backward function)  : 160 bytes
free vars captured          : ('other', 'self', 't')
closure จับ t ตัวเองด้วยไหม  : True     <- วงกลม

root ตายทันทีที่ refcount หมด  : False
ตายตอน gc.collect()            : True, 23 objects

ราคาของ closure ไม่ใช่ “เปลือง RAM เพราะ copy ข้อมูล” — แต่คือ node ทุกตัวตายช้ากว่าที่ควร เพราะเป็นวงกลม
เทรน 100 รอบสร้างทิ้งราว 34,000 ก้อน · ไม่มีก้อนไหนถูกปล่อยทันทีเลยสักก้อน
