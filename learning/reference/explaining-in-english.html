ทางแก้จึงไม่ใช่ “ฝึกภาษาอังกฤษให้เก่งขึ้น” ซึ่งช้าและวัดผลไม่ได้ — แต่คือลดภาระของงานใดงานหนึ่งลง ซึ่งทำได้ทันที

6 วิธี เรียงตามผลตอบแทน

1 ⭐ แยกสองงานออกจากกัน

วางโครงเป็นภาษาไทยหรือเป็น bullet ก่อน แล้วค่อยพูดอังกฤษตามโครง — อย่าแต่งโครงกับแต่งประโยคพร้อมกัน

พอโครงถูกวางไว้ล่วงหน้า สมองทั้งก้อนไปอยู่ที่ประโยคได้

2 ⭐ ใช้โครงเดิมทุกครั้ง

ถ้าโครงเหมือนเดิม การตัดสินใจเรื่องโครงถูกทำไปแล้วล่วงหน้า — นี่คือคำตอบตรงๆ ของ “ไม่รู้จะพูด detail ขนาดไหน” (ดูโครงถาวรข้างล่าง)

3 ⭐ เลิกกังวลไวยากรณ์ตอนพูด

ข้อผิดที่กังวลอยู่ คือข้อผิดที่มีผลน้อยที่สุด 
"the neuron have two parameter"      ← ผิด 2 ที่ ไม่มีใครเข้าใจผิดเลย
"the gradient tells you the value"   ← ถูกทุกตัว แต่ความหมายผิด

s กับ the แทบไม่พาความหมายเลย — ความคล่องสำคัญกว่าความถูกต้อง สำหรับการพูด เก็บความถูกต้องไว้ให้งานเขียนซึ่งมีเวลาแก้

การหยุดกลางประโยคเพื่อเช็ค s ทำให้เสียโครงสร้างซึ่งเป็นสิ่งที่สำคัญจริงๆ — จ่ายของแพงเพื่อซื้อของถูก

4 สะสมวลี ไม่ใช่คำ

อังกฤษเชิงเทคนิควิ่งด้วยวลีสำเร็จรูป — จำได้แล้วมันจะออกมาเองโดยไม่กินสมาธิ

วลีใช้ตอน
the derivative of X with respect to Yพูดถึงอนุพันธ์ ← ใช้ถูกอยู่แล้ว
the gradient flows backward through the graphอธิบาย backward pass
the key insight is that …ก่อนพูดข้อที่สำคัญที่สุด
this boils down to …ย่อเรื่องซับซ้อนให้เหลือแก่น
it turns out that …เกริ่นผลที่น่าประหลาดใจ
what this buys us is …บอกว่าได้อะไรจากการทำแบบนี้
the catch is that …บอกข้อเสียหรือข้อแลกเปลี่ยน
rather than X, we …เทียบทางเลือก
X comes for freeได้มาโดยไม่ต้องทำเพิ่ม
we fall back to Xทางถอย (เช่น reflected operator)
this fails silentlyผิดโดยไม่มี error ← ธีมของทั้งเดือน
X is a special case of Ygradient เป็นกรณีพิเศษของ Jacobian

เพิ่มเข้าตารางนี้ทุกครั้งที่เจอวลีที่อยากใช้แต่นึกไม่ออกตอนพูด

5 อธิบายเรื่องเดิม 3 ความยาว

30 วินาทีแก่นล้วน
3 นาทีแก่น + ตัวอย่างหนึ่ง
15 นาทีเต็ม

ความสามารถในการย่อคือทักษะที่ตอบคำถาม “ลงลึกแค่ไหน” — และในสัมภาษณ์จริง เขาถามสั้นก่อนเสมอ แล้วค่อยเจาะลงไปตามที่เขาสนใจ

6 เขียนก่อน พูดทีหลัง — สำหรับเนื้อหาใหม่

การเขียนให้เวลาเรียบเรียง พอเขียนแล้ว การพูดจะกลายเป็นการระลึกสิ่งที่เรียบเรียงไว้แล้ว ไม่ใช่การแต่งสด — README.md จะทำหน้าที่นี้ให้เอง

กฎเดียวที่ตอบว่า “ลงลึกแค่ไหน”

รายละเอียดที่ใส่ ต้องเป็นสิ่งที่คนฟังต้องรู้เพื่อเข้าใจประโยคถัดไป เท่านั้น

ตัวอย่างจริงจากรอบที่พูด: อธิบายว่า neuron ที่มีหลาย input ต้องมี W1x1 + W2x2 + W3x3 — แต่ประโยคถัดไปคือ backprop ซึ่งไม่ต้องใช้ข้อมูลนั้นเลย ตัดออกได้ทั้งท่อน

ความรู้สึกว่า “ไม่มีเวลาอธิบาย เพราะ detail เยอะมาก” คือสัญญาณว่าใส่ detail ผิดที่ ไม่ใช่ว่าเวลาไม่พอ

โครงถาวร — ใช้ซ้ำได้ทุกครั้ง

1. WHY            What problem were people trying to solve?
2. WHAT           A neural network is a computational graph.
3. HOW            Training = predict → measure the error → adjust.
4. THE HARD PART  Numerical gradients need one forward pass per parameter.
                  With a billion parameters that is a billion passes.
5. THE ANSWER     Backprop: one backward pass, all the gradients.
                  It works because intermediate results are reused.
6. PROOF          I built it from scratch. Here is the graph it draws.

“There's a better question than that: what problem are people trying to solve?” ไม่แนะนำศัพท์ก่อนแนะนำปัญหาที่ศัพท์นั้นแก้ — ครูที่สอนดีใช้วิธีนี้ คนส่วนใหญ่ไม่ทำ
iPhone เลือกข้อความจากรูป ตัวอย่างที่คนฟังเคยใช้เอง ไม่ใช่ตัวอย่างในตำรา
มีดกับการทำอาหาร ตอบ “ทำไมต้องเรียนของพื้นฐาน” ได้ในประโยคเดียว
numerical gradient ช้าเกินไป เหตุผลจริงที่ backprop มีอยู่ — ไม่ใช่คำอธิบายลอยๆ

จุดที่ยังขาด

“Backprop runs one backward pass and gives you all the gradients” — นี่คือการอ้าง ไม่ใช่คำอธิบาย
สิ่งที่ขาดคือ ทำไมมันทำได้: ผลลัพธ์กลางทางถูกใช้ซ้ำ — gradient ที่คำนวณให้ node หนึ่ง ถูกส่งต่อให้ทุก node ที่อยู่ใต้มัน โดยไม่ต้องคำนวณใหม่

วิธีวัดว่าดีขึ้นจริง: อัดเสียงตัวเองทุกครั้ง แล้วนับว่าหยุดกี่ครั้ง — ไม่ใช่นับว่าผิดไวยากรณ์กี่ที่ · จำนวนครั้งที่หยุดคือตัวชี้วัดของ working memory ที่เหลืออยู่
