Data structures ที่ Zero to Hero ใช้จริง

รายการที่ปิดจบได้ — ไม่ใช่หลักสูตร CS ทั้งใบ แต่คือของที่จะโผล่มาจริงในวิดีโอทั้งแปดตอน พร้อมบอกว่าโผล่ตอนไหน เพื่อให้เก็บได้ตอนที่มันมีบริบทแล้ว ไม่ใช่เรียนล่วงหน้าแล้วลืม

ช่องว่างไม่ใช่ ความรู้ เรื่อง data structure — เพราะพวกนั้น derive เองไปแล้วทุกข้อ ช่องว่างคือ ชั่วโมงบินในการเลือก โครงสร้างจากคุณสมบัติของมัน ซึ่งเป็นทักษะที่ได้จากการทำซ้ำอย่างเดียว ไม่มีทางลัด และวิดีโอไม่ได้แสดงส่วนนี้ให้ดู เพราะคนในวิดีโอเลือกเสร็จไปตั้งแต่ก่อนกดอัด

กรอบตัดสินใจ 4 คำถาม — ครอบคลุม 95% ของโค้ดทั้งซีรีส์

ทุกครั้งที่ต้องเลือกว่าจะเก็บของใน list / set / dict / tuple ถามสี่ข้อนี้ตามลำดับ แล้วคำตอบจะบังคับตัวเอง:

#คำถามถ้าใช่
1ลำดับสำคัญไหม — ต้องรู้ว่าอันไหนมาก่อนมาหลังlist / tuple เท่านั้น
2ต้องถามว่า “มีอันนี้อยู่แล้วหรือยัง” บ่อยไหมset / dict — เพราะ in เป็น O(1)
3ของซ้ำสำคัญไหม — เก็บ 2 อันที่เหมือนกันแล้วต้องเห็นทั้งคู่list · ถ้าไม่สำคัญ set ตัดให้ฟรี
4ต้องเอาไปเป็น key ของ dict หรือสมาชิกของ set ไหมต้อง hashable = ต้อง immutable → tuple ไม่ใช่ list

ลองย้อนดู trace() ที่เขียนเอง — ทุกการตัดสินใจในนั้นตกลงมาจากตารางนี้พอดี:

ของเลือกอะไรข้อไหนบังคับ
nodessetข้อ 3 — node เดียวกันห้ามโผล่สองครั้ง
visited guardset (ตัวเดียวกับ nodes)ข้อ 2 — ถามว่า “เคยไปหรือยัง” ทุกครั้งที่เรียก
edgesset ของ tupleข้อ 3 + ข้อ 4 — เส้นซ้ำห้ามมี และ list เป็นสมาชิกของ set ไม่ได้
_prevlist / tupleข้อ 1 + ข้อ 3 — x - y สลับข้างแล้วคนละความหมาย และ x + x ต้องเห็น x สองครั้ง
ลำดับ topologicallistข้อ 1 — ทั้งหมดของมันคือลำดับ
จุดที่พลาดได้ง่ายและเจ็บ

_prev ต้องเป็น list ไม่ใช่ set ทั้งที่ nodes เป็น set — สองที่นี้ตอบคนละคำถามกัน nodes ถามว่า “กราฟนี้มี node อะไรบ้าง” (ห้ามซ้ำ) ส่วน _prev ถามว่า “ฉันเกิดจากอะไรบวกอะไร” (ซ้ำได้ และเรียงสำคัญ) ถ้าเผลอทำ _prev เป็น set แล้วเขียน x + x จะเหลือ x ตัวเดียว แล้ว gradient จะผิดเป็น 1 แทนที่จะเป็น 2 — เงียบๆ

ราคาของแต่ละ operation — ตารางที่ควรจำ

Big-O ไม่ได้บอกว่าเร็วกี่วินาที มันบอกว่าช้าลงเท่าไหร่เมื่อของเยอะขึ้น — ซึ่งเป็นคำถามที่ถูกต้องกว่า

operationlistsetdictหมายเหตุ
x in cO(n)O(1)O(1)ตัวที่ทำให้ guard เร็วขึ้น 7 เท่า
เพิ่มท้ายO(1)*O(1)O(1)* amortized — บางครั้งขยายหน่วยความจำ
เข้าถึงด้วย index / keyO(1)—O(1)set ไม่มี index เลย
แทรกหน้าสุด insert(0, x)O(n)——ต้องเลื่อนทุกตัว — ระวังตอนสร้างลำดับย้อนกลับ
กลับด้าน reversed()O(1)——คืน iterator ไม่ได้ copy
รักษาลำดับที่ใส่ใช่ไม่ใช่ (Python 3.7+)เป็นการรับประกันของภาษาแล้ว ไม่ใช่ผลข้างเคียง

แถวแรกคือที่มาของตัวเลข 13.4 µs → 1.77 µs ที่วัดได้เอง ถ้า guard ใช้ list แทน set ตัวเลขนั้นจะกลับมาแย่อีกครั้ง และแย่ลงเรื่อยๆ ตามขนาดกราฟ — ซึ่งใน MLP จริงคือหลักหมื่น node

ทำไม set ถึงตอบ in ได้ O(1)

ข้างใต้ set และ dict คือ hash table เหมือนกัน หลักการมีบรรทัดเดียว: เอาค่าไปคำนวณเป็นตัวเลขก่อน แล้วใช้ตัวเลขนั้นเป็นที่อยู่ จึงกระโดดไปดูตรงจุดเดียวได้เลย ไม่ต้องไล่ทีละตัว

ผลที่ตามมาสามข้อ — และทั้งสามข้อเคยเจอมาแล้ววันแรก:

ผลที่ตามมาเจอตอนไหน
ของที่เปลี่ยนค่าได้ (list, dict) เป็น key ไม่ได้ — เพราะเปลี่ยนค่าแล้วที่อยู่จะเพี้ยน ตอน edges ต้องเป็น tuple ไม่ใช่ list
ไม่มีลำดับ เพราะที่อยู่มาจาก hash ไม่ได้มาจากเวลาที่ใส่ ตอนถามว่า “แล้วเราจะรู้ลำดับไหม” — คำตอบคือไม่ และนั่นคือเหตุผลที่ต้องมี topological order แยกต่างหาก
เขียน __eq__ เองเมื่อไหร่ __hash__ หายทันที object นั้นใส่ set ไม่ได้อีก เหตุผลที่ Value ยังไม่มี __eq__ และควรเป็นแบบนั้นไปตลอดเดือนนี้
ทำไม Value ถึงใส่ set ได้ทั้งที่ไม่ได้เขียนอะไรเพิ่ม

Python ให้ __hash__ เริ่มต้นมาจาก identity ของ object (ประมาณ id()) — แปลว่า Value(2.0) สองตัวที่ค่าเท่ากันเป๊ะ ยังนับเป็นคนละตัวใน set ซึ่งถูกต้องแล้วสำหรับ computation graph เพราะเราสนใจว่า “เป็น node เดียวกันไหม” ไม่ใช่ “ค่าเท่ากันไหม”

ระดับที่ 2 — อัลกอริทึมบนกราฟ (เดือนนี้ปิดจบได้เลย)

เรื่องสถานะทำไมต้องรู้
DAG · node · edge✅ ทำแล้วรูปทรงของทุกโมเดลตั้งแต่ micrograd ถึง GPT
DFS แบบ recursive + visited set✅ ทำแล้วโครงหลักของ trace() และของ topological sort
Topological sort⏳ กำลังทำลำดับที่ทำให้ backward pass ถูกต้อง
Stack — และ call stack คือ stackรู้ครึ่งเดียวDFS แบบไม่ recursive คือ DFS + stack ที่ถือเอง · RecursionError คือ stack เต็ม
BFS + queueยังไม่ได้ทำคู่แฝดของ DFS ต่างกันแค่ “เอาตัวถัดไปจากหัวหรือจากท้าย” — ใช้เวลา 20 นาที
อันนี้คุ้มที่สุดในตาราง

DFS กับ BFS คือโค้ดเดียวกัน ต่างกันที่โครงสร้างที่ใช้เก็บ “ยังไม่ได้ไป” — ถ้าเป็น stack (เอาตัวหลังสุดออกก่อน) ได้ DFS · ถ้าเป็น queue (เอาตัวแรกสุดออกก่อน) ได้ BFS เข้าใจประโยคนี้ประโยคเดียว = ปิดหัวข้อ “graph traversal” ทั้งหัวข้อ และเป็นตัวอย่างที่ชัดที่สุดว่า การเลือกโครงสร้างข้อมูลเปลี่ยนพฤติกรรมของอัลกอริทึม

ระดับที่ 3 — array กับ strides (จุดที่คุ้มที่สุดสำหรับ ML)

พอถึง makemore โครงสร้างจะเปลี่ยนจากกราฟเป็น array และนี่คือจุดที่การคิดแบบ data structure ให้ผลตอบแทนสูงที่สุดในทั้งซีรีส์ เพราะมันอธิบายพฤติกรรมของ PyTorch ที่คนส่วนใหญ่ท่องจำเอา

นิยามของ tensor ที่ทำให้ทุกอย่างเข้าที่

tensor = บล็อกหน่วยความจำเรียงติดกันเป็นเส้นเดียว + shape + strides (ต้องกระโดดกี่ช่องเพื่อขยับ 1 ก้าวในแต่ละแกน)
ตัวเลขไม่เคยถูกจัดเป็นตารางจริงเลย — ความเป็น 2 มิติทั้งหมดอยู่ใน strides

คำสั่งเกิดอะไรขึ้นจริงcopy ไหม
x.view(...) / reshapeแก้แค่ shape กับ strides ข้อมูลไม่ขยับไม่ — จึงฟรี
x.T / transposeสลับตัวเลขใน strides เฉยๆไม่
x.contiguous()เขียนหน่วยความจำใหม่ให้เรียงตรงกับ shapeใช่ — จึงมีอยู่เพราะ transpose ไม่ copy
broadcastingแกล้งทำเป็นว่าแกนนั้นมี stride = 0 (ก้าวแล้วอยู่ที่เดิม)ไม่
C[X] — gather / embedding lookupไล่หยิบทีละแถวตาม index ไปวางในบล็อกใหม่ใช่

แถวสุดท้ายคือ embedding table ของ makemore ตอนที่ 2 ทั้งดุ้น — C[X] ไม่ใช่การคูณเมทริกซ์ มันคือการหยิบแถว เฉยๆ

เส้นเชื่อมตรงจากบทเรียนวันนี้

backward ของ C[X] คือ scatter-add — และเหตุผลที่ต้องเป็น add ไม่ใช่ set คือเหตุผลเดียวกันเป๊ะกับที่ _backward ต้องใช้ +=: ตัวอักษรเดียวกันถูกหยิบหลายครั้งใน batch เดียว = node เดียวมีพ่อแม่หลายตัว = ต้องบวกสะสมทุกเส้นทาง
สิ่งที่กำลังทำอยู่ตอนนี้ไม่ใช่ของเล่นสำหรับกราฟเล็กๆ — มันคือกฎเดียวกันที่ PyTorch ใช้จริง

ไม่โผล่ใน Zero to Hero เลยแม้แต่ครั้งเดียว
  • Linked list (Python มี list ที่เป็น dynamic array อยู่แล้ว)
  • Balanced BST — AVL, red-black tree

วิธีเก็บระหว่างทาง — กฎ 3 ข้อ

  1. ห้ามเรียนล่วงหน้า — รอให้โครงสร้างนั้นโผล่มาในโค้ดที่กำลังเขียนจริงก่อน ความรู้ที่ไม่มีที่ให้เกาะจะหายไปภายในหนึ่งสัปดาห์
  2. เจอแล้วหยุด 30 นาที — ถามสามข้อ: มันรับประกันอะไร? อะไรที่มันทำไม่ได้? ทางเลือกอื่นคืออะไร แล้วทำไมถึงแพ้? จบแล้วกลับไปเขียนโค้ดต่อ
  3. จดลง learning-records/ เป็น “ตอนแรกคิดว่า X แต่จริงๆ คือ Y” รูปแบบนี้จำได้ทนกว่านิยาม เพราะมันผูกกับความประหลาดใจ
