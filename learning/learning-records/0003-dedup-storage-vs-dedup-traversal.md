# 0003 — dedup ที่ตัวเก็บ ไม่ใช่ dedup ที่การเดิน

**วันที่:** 2026-08-08
**สถานะ:** ยังแก้ไม่เสร็จ — งานค้างของวันถัดไป

## บริบท

พบว่ากราฟเป็น DAG (ดู [0001](0001-graph-is-a-dag-not-a-tree.md)) จึงเปลี่ยน
`nodes` จาก `list` เป็น `set` เพื่อกันซ้ำ ผลคือ `x*y + x` ได้ 4 node ถูกต้อง
จึงคิดว่าปัญหาจบแล้ว

## สิ่งที่พบ

**ไม่จบ** — `set` แก้แค่ "การเก็บ" ส่วน "การเดิน" ยังลงไปที่ node เดิมซ้ำอยู่ดี

หลักฐานสองชิ้น:

```
w = (p*q) + (p*q)   →  nodes=4  edges=6   ← edge ควรได้ 3 ทุกเส้นซ้ำ

depth   nodes        calls
   18      19      524,287                ← 19 node แต่เดินครึ่งล้านครั้ง
```

## บทเรียน

> การกันซ้ำที่ container ไม่ได้กันซ้ำที่ recursion —
> การ์ดต้องอยู่ที่ตัว recursion ก่อนที่จะเรียกตัวเองลงไป

`set` ตอบว่า "มีอะไรอยู่ในถุงบ้าง" แต่ไม่ได้ห้ามไม่ให้เดินเข้าไปซ้ำ

## หมายเหตุที่เกี่ยวข้อง

`set` **ไม่มีลำดับ** — ใส่ `a,b,c,d,e` แล้ววนออกมาได้ `e,a,d,c,b`
ตอนนี้ไม่เป็นไรเพราะงานคือ "มีอะไรบ้าง" ไม่ใช่ "เรียงยังไง"
แต่ตอน backward จะต้องการทั้งสองอย่างพร้อมกัน — นั่นคือที่มาของ topological sort

## คำถามที่ยังเปิด

เจอ node ซ้ำแล้วควร `return` ทันที หรือไม่เก็บแต่เดินลึกต่อ?
สองอย่างนี้ให้ผลไม่เหมือนกันทั้งด้านความถูกต้องและด้านความเร็ว
