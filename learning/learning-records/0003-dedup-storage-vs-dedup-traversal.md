# 0003 — dedup ที่ตัวเก็บ ไม่ใช่ dedup ที่การเดิน

**วันที่:** 2026-08-08
**สถานะ:** ✅ แก้แล้ว 2026-08-09 — ดูหัวข้อ "บทสรุป" ท้ายไฟล์

## บริบท

พบว่ากราฟเป็น DAG (ดู [0001](0001-graph-is-a-dag-not-a-tree.md)) จึงเปลี่ยน
`nodes` จาก `list` เป็น `set` เพื่อกันซ้ำ ผลคือ `x*y + x` ได้ 4 node ถูกต้อง
จึงคิดว่าปัญหาจบแล้ว

## สิ่งที่พบ

**ไม่จบ** — `set` แก้แค่ "การเก็บ" ส่วน "การเดิน" ยังลงไปที่ node เดิมซ้ำอยู่ดี

หลักฐานสองชิ้น:

```
w = (p*q) + (p*q)   →  nodes=4  edges=6   ← edge ควรได้ 3 ทุกเส้นซ้ำ

depth   nodes        calls
   18      19      524,287                ← 19 node แต่เดินครึ่งล้านครั้ง
```

## บทเรียน

> การกันซ้ำที่ container ไม่ได้กันซ้ำที่ recursion —
> การ์ดต้องอยู่ที่ตัว recursion ก่อนที่จะเรียกตัวเองลงไป

`set` ตอบว่า "มีอะไรอยู่ในถุงบ้าง" แต่ไม่ได้ห้ามไม่ให้เดินเข้าไปซ้ำ

## หมายเหตุที่เกี่ยวข้อง

`set` **ไม่มีลำดับ** — ใส่ `a,b,c,d,e` แล้ววนออกมาได้ `e,a,d,c,b`
ตอนนี้ไม่เป็นไรเพราะงานคือ "มีอะไรบ้าง" ไม่ใช่ "เรียงยังไง"
แต่ตอน backward จะต้องการทั้งสองอย่างพร้อมกัน — นั่นคือที่มาของ topological sort

---

## บทสรุป (2026-08-09)

ต้องแก้ **สองจุด** ไม่ใช่จุดเดียว — และแต่ละจุดแก้คนละอาการ:

| แก้อะไร | แก้อาการไหน |
|---|---|
| **guard ที่ต้นทางของ `f`** | เดินเข้าไปในกิ่งที่เคยเดินแล้วซ้ำ (ต้นเหตุของ 2ⁿ) |
| **`edges` เป็น `set`** | `_prev` มีลูกตัวเดียวกันสองช่องจริง (`w = e + e`) — guard แตะไม่ถึง |

ตารางวัดผลทั้ง 4 ชุดค่าผสม:

```
edges เป็น   guard | w=e+e: edges | deep18: calls
      list     ไม่ |            6 |       524,287
      list     ใช่ |            4 |            37
       set     ไม่ |            3 |       524,287
       set     ใช่ |            3 |            37     ← ถูกทั้งคู่
```

### ตำแหน่งของ guard — สองแบบ ให้ผลเท่ากัน แต่สัญญาต่างกัน

| | เช็คในตัว `f` (ที่เลือกใช้) | เช็คก่อนเรียก `f` |
|---|---|---|
| จำนวน call (ลึก 18) | 37 | 19 |
| สัญญาของ `f` | **เรียกกี่ครั้งก็ปลอดภัย** | ผู้เรียกต้องเช็คเอง |
| ถ้ามีที่เรียกหลายจุด | ปลอดภัยอัตโนมัติ | ลืมจุดเดียวพัง |

**หลักการที่กว้างกว่านั้น:** เงื่อนไขความปลอดภัยที่อยู่*ในตัวฟังก์ชัน* ผิดไม่ได้
ส่วนที่อยู่*ที่ผู้เรียก* ผิดได้ทุกครั้งที่มีคนเรียกเพิ่ม

### ผลที่วัดได้จริงหลังแก้

```
%%timeit  trace_no_guard(h)    →  13.4 µs
%%timeit  trace_with_guard(h)  →   1.77 µs      (เร็วขึ้น 7.6 เท่า บนกราฟ 6 ชั้น)
```

### ยังเปิดอยู่

`w = e + e` ควรได้ `dw/de = 2` แต่ตอนนี้กราฟเหลือลูกศรเส้นเดียว —
โค้ดจะรู้เรื่องนั้นได้ยังไง? เก็บไว้ตอบตอนเขียน `backward()`
