# 0001 — computation graph เป็น DAG ไม่ใช่ tree

**วันที่:** 2026-08-08
**สถานะ:** ยืนยันแล้วด้วยการทดลอง

## บริบท

ตอนเริ่มออกแบบ `Value` ใช้คำว่า "tree" มาตลอด และคิดว่าจะเดินกราฟแบบ tree

## สิ่งที่พบ

สำหรับ `z = x * y + x` — `x` ที่อยู่ใต้ `(x*y)` กับ `x` ที่ถูกบวกตรงๆ
เป็น **object ก้อนเดียวกัน**:

```
left_x is right_x           → True
id(left_x) == id(right_x)   → True
```

Python ไม่ได้ก๊อป object ให้ กราฟจึงมี 4 node / 4 edge
โดยที่ `x` เป็นต้นทางของลูกศรสองเส้น

- **tree** = ทุก node มีพ่อแม่ได้ไม่เกิน 1 ตัว
- **DAG** = มีทิศทาง ไม่มีวงจร แต่มาบรรจบกันได้ ← อันนี้

## ทำไมสำคัญ

"การมาบรรจบกัน" ไม่ใช่กรณีขอบ — ในโครงข่ายจริง น้ำหนักทุกตัวถูกใช้ซ้ำหลายที่เสมอ
ถ้ายังคิดว่าเป็น tree จะเข้าใจ backpropagation ผิดตั้งแต่ฐาน

## ผลที่ตามมา

- ที่เก็บ node ต้องกันซ้ำ → ใช้ `set`
- การเดินกราฟต้องกันซ้ำด้วย (คนละเรื่องกับข้อบน — ดู [0003](0003-dedup-storage-vs-dedup-traversal.md))
- **ยังไม่ได้ตรวจสอบ:** เรื่องนี้กระทบ gradient ยังไง — เก็บไว้ค้นพบเองตอนเขียน `backward()`
