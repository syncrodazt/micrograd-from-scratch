Lesson 01 · micrograd

Value ที่จำที่มาของตัวเองได้

หัวใจของ autograd ไม่ใช่แคลคูลัส แต่เป็นการตัดสินใจว่า “ตัวเลขหนึ่งตัวต้องจำอะไรไว้บ้าง” — และคำตอบนั้นเปลี่ยนเลขให้กลายเป็นกราฟ

2026-08-08 · Day 2 · M1 micrograd

ปัญหาที่ทำให้ต้องมี Value

เริ่มจากสิ่งที่ทำได้อยู่แล้ว — หาความชันด้วยนิยามตรงๆ ของอนุพันธ์: 

h = 0.001
a = 2.0; b = -3.0; c = 10.0
d1 = a * b + c

a = 2.0 + h
d2 = a * b + c

(d2 - d1) / h        # -3.0000000000001137

นี่คือ numerical gradient — ถูกต้อง แต่ใช้จริงไม่ได้

มันได้คำตอบ แต่มีปัญหาสองข้อที่ฆ่ามันทิ้ง:

  • ต้องคำนวณใหม่ทั้งเครือข่ายหนึ่งรอบต่อพารามิเตอร์หนึ่งตัว — โมเดลที่มีพารามิเตอร์ล้านตัวก็ต้องคำนวณล้านรอบ
  • ค่าที่ได้ไม่แม่น — -3.0000000000001137 ไม่ใช่ -3.0 เพราะการลบเลขทศนิยมสองตัวที่ใกล้กันมากทำให้เสียนัยสำคัญ (catastrophic cancellation)

สิ่งที่ต้องการคือ reverse-mode autodiff: เดินย้อนกลับ ครั้งเดียว แล้วได้ gradient ของทุกตัวพร้อมกัน แต่การจะเดินย้อนกลับได้ ต้องมีอะไรให้เดิน — และ float ธรรมดาไม่มี

float ลืมทุกอย่างทันทีที่คำนวณเสร็จ

ทดลองในหัว: ถ้ามีคนยื่นตัวเลข -1.0 มาให้ แล้วถามว่ามันเกิดจากอะไร — ตอบไม่ได้ อาจเป็น 2 - 3 หรือ -0.5 × 2 หรืออะไรก็ได้

ผลลัพธ์ของ a + b ในภาษาโปรแกรมทั่วไป เก็บแค่ค่า ไม่เก็บที่มา ประวัติถูกทิ้งไปตอนที่ฟังก์ชัน return

แนวคิดหลัก

งานของ autograd engine คือ ไม่ทิ้งประวัตินั้น — ทำให้ผลลัพธ์ทุกตัวแบกข้อมูลว่า “ฉันเกิดจากใคร ด้วยวิธีอะไร” ติดตัวไปด้วย ผลรวมของการไม่ทิ้งนี้คือ computation graph

node หนึ่งตัวต้องจำอะไรบ้าง

หาคำตอบด้วยการทำงานย้อนกลับจากเป้าหมาย — ถ้าให้ d มาตัวเดียว แล้วสั่งให้วาดรูปนี้ให้ได้ ต้องมีข้อมูลอะไรติดอยู่ใน d? 

  a ─┐
     ├─[ + ]─→ d
  b ─┘

ไล่ทีละอย่างในรูป: มีกล่อง มีลูกศร มีป้ายกำกับตรงกลาง — ได้คำตอบสี่ช่อง

ช่องเก็บอะไรตอบคำถามในรูปว่า
dataค่าตัวเลขในกล่องเขียนว่าอะไร
_prevnode ที่ทำให้เกิดตัวนี้ลูกศรมาจากไหนบ้าง
_opoperation ที่ใช้สร้างป้ายตรงกลางเขียนว่าอะไร
labelชื่อไว้อ่านกล่องนี้ชื่ออะไร

_prev และ _op ขึ้นต้นด้วย _ ตามธรรมเนียม Python ที่แปลว่า “ของภายใน ไม่ใช่ API ที่คนใช้ควรไปยุ่ง” — Python ไม่ได้บังคับอะไร มันแค่ส่งสัญญาณให้คนอ่าน

กราฟถูกสร้างขึ้นระหว่างที่คำนวณ ไม่ใช่หลังจากนั้น

จุดที่สวยที่สุดของ micrograd อยู่ตรงนี้: เราไม่ได้เขียนโค้ดสร้างกราฟแยกต่างหาก — กราฟโผล่ขึ้นมาเป็นผลพลอยได้ของการบวกลบคูณหาร

กลไกคือ operator overloading: เขียน dunder method ชื่อ __add__ ไว้ แล้ว Python จะเรียกให้เองทุกครั้งที่เจอเครื่องหมาย +

เราเขียนPython เรียก
a + ba.__add__(b)
a * ba.__mul__(b)
-aa.__neg__()
a ** ba.__pow__(b)
a เฉยๆ ใน notebooka.__repr__()

ใน __add__ คือนาทีเดียวเท่านั้นที่โค้ดรู้ว่า “ตัวใหม่นี้เกิดจาก self กับ other ด้วยวิธี +” ถ้าไม่แนบข้อมูลนั้นติดไปกับตัวที่ return ความรู้จะหายทันที

ผลลัพธ์

โค้ดที่คนเขียนยังหน้าตาเหมือนเลขคณิตธรรมดา — d = a * b + c — แต่ข้างในมีกราฟ 5 node ถูกประกอบขึ้นเรียบร้อยแล้ว นี่คือเหตุผลที่ PyTorch เขียนโมเดลได้เหมือนเขียนสมการ

สองกับดักที่เจอจริงระหว่างเขียน

1. ค่า default ที่แก้ได้ จะถูกแชร์กันทั้งโปรแกรม

_prev ต้องมีค่าเริ่มต้นเป็น “ว่าง” เพราะ leaf ไม่ได้เกิดจากการคำนวณ แต่เขียนแบบนี้ไม่ได้: 

def __init__(self, data, _prev=[]):   # ระเบิด

Mutable default argument — [] ถูกสร้างครั้งเดียวตอน Python อ่านบรรทัด def ทุก object ที่ไม่ส่ง _prev มาจะแชร์ list ก้อนเดียวกัน พิสูจน์ได้ใน 20 วินาที: 

def add_item(x, bucket=[]):
    bucket.append(x)
    return bucket

add_item(1)   # [1]
add_item(2)   # [1, 2]   ← ไม่ใช่ [2]
add_item(3)   # [1, 2, 3]

ทางแก้: ใช้ tuple ว่าง () ซึ่งแก้ไม่ได้จึงแชร์ได้ปลอดภัย แล้วแปลงเป็น list ข้างใน

2. ถ้าไม่มี __repr__ จะดีบักไม่ได้เลย

ไม่เขียนแล้วได้ <__main__.Value object at 0x000001A2...> ซึ่งไม่บอกอะไรเลย __repr__ ไม่ใช่ของประดับ — มันคือเครื่องมือดีบักหลักตลอดทั้งเดือน

เกร็ดที่ได้ใช้ทันที

เลข 0x000001A2... ในข้อความนั้นคือ id() ของ object — และมันจะกลายเป็นคำตอบของอีกปัญหาหนึ่งใน Lesson 03 พอดี

ตรวจตัวเอง

  1. ทำไม __add__ ต้อง คืน object ใหม่ แทนที่จะแก้ self?
  2. 3 * a จะพังทั้งที่ a * 3 ทำงานได้ — เพราะอะไร และแก้ด้วยเมธอดชื่ออะไร? (reflected operator)
  3. ถ้าลบ _op ออกจาก Value จะยังคำนวณ forward ได้ไหม? แล้วอะไรจะพัง?
