Training loop
สี่บรรทัดที่ทำให้มันเรียนรู้ได้

วันที่ทุกอย่างมาบรรจบ — และวันที่บั๊กที่ roadmap ทำนายไว้ตั้งแต่ต้นเดือน โผล่ออกมาจริงๆ แล้วถูกจับได้เอง

2026-08-12 · Day 6 · ปิดเฟส 4

สี่ขั้น และลำดับที่ห้ามสลับ

#ขั้นทำอะไร
1forwardเอา input ผ่านเครือข่าย ได้คำทำนาย
2lossยุบคำทำนายทั้งหมดกับเป้าหมาย ให้เหลือ ตัวเลขตัวเดียว
3backwardเดินย้อนจาก loss ไปกรอก grad ให้ทุก parameter
4updateขยับ parameter สวนทาง gradient
0zero_gradล้าง grad ก่อนรอบถัดไป — ขั้นที่ไม่มีในตำราไหนเขียนเป็นขั้นตอน แต่ขาดไม่ได้

ขั้นที่ 5 จะวางไว้ต้นรอบหรือท้ายรอบก็ได้ผลเหมือนกัน — ขอแค่มันอยู่ระหว่าง backward() สองครั้ง

บั๊กที่ roadmap ทำนายไว้ตั้งแต่ต้นเดือน

“ตอนที่ลืม set gradient เป็น 0 มันเหมือนไม่ลู่เข้า อยู่ดีๆ ก็เปลี่ยนค่า พอเซ็ตเป็นศูนย์ทุกครั้งก่อน forward pass ใหม่ ก็ไม่มีปัญหาแล้ว”

วัดจริง — เรียก backward() ซ้ำโดยไม่ล้างอะไรเลย ดู parameter ตัวเดียวกัน: 

รอบ 1   p.grad = +0.565647
รอบ 2   p.grad = +1.131295
รอบ 3   p.grad = +1.696942
รอบ 4   p.grad = +2.262590
รอบ 5   p.grad = +2.828237

โตเป็นเส้นตรง ไม่มีขอบเขต — ก้าวยิ่งรอบยิ่งใหญ่ จนกระเด็นออกนอกหุบ
รอบที่ 100 จะเป็น 56 · รอบที่ 1000 เป็น 565

ทำไมล้างเฉพาะ parameter

ตัวกลางไม่ต้องล้าง เพราะมันไม่ได้อยู่ให้ล้าง — forward pass แต่ละรอบสร้าง Value ชุดใหม่ทั้งหมด ของรอบก่อนตายไปแล้ว และของใหม่เกิดมาพร้อม grad = 0.0 อยู่แล้ว

มีแค่ parameter ที่รอดข้ามรอบ จึงมีแค่ parameter ที่สะสมของเก่าได้

วัดกับ MLP(3, [4, 4, 1]): forward pass เดียวสร้าง 85 ก้อน · มี 41 parameter ที่อยู่ต่อ · เทรน 4 ตัวอย่าง × 100 รอบ = สร้างทิ้งราว 34,000 ก้อน เหลือ 41

ลืม zero_grad ≠ momentum

ลืม zero_gradMomentum
สูตรg₁+g₂+…+g_kv ← βv + g (β ≈ 0.9)
ของเก่าน้ำหนักเท่าเดิมตลอดกาลจางลงแบบเรขาคณิต
ขนาดโตไม่มีที่สิ้นสุดมีเพดานที่ ~g/(1−β)

สัญชาตญาณที่ว่า “ทิศทางเก่ายังมีค่า” ถูกต้อง — นั่นคือไอเดียเบื้องหลัง momentum จริงๆ ลืม zero_grad คือ momentum ที่ β = 1 ซึ่งคือความต่างระหว่างเทคนิคที่ใช้ได้ กับบั๊ก

เส้นที่ต้องแยกให้ขาด: การสะสมภายใน 1 step เป็นสิ่งที่ต้องการ (บวก gradient จากทุกตัวอย่างใน batch) · ที่ผิดคือสะสมข้าม step

เครื่องหมายของการอัปเดต — derive ได้ ไม่ต้องจำ

gradแปลว่าอยากได้−lr·grad
+2เพิ่ม p แล้ว loss เพิ่มลด pติดลบ → p ลด ✅
−3เพิ่ม p แล้ว loss ลดเพิ่ม pติดบวก → p เพิ่ม ✅

ไม่ต้องมี if เลย — เครื่องหมายของ gradient จัดการทั้งสองกรณีเอง เก็บประโยคเดียวไว้พอ:

grad บอกทางที่ loss จะ เพิ่ม — เดินสวนทางเสมอ

และนี่คือเหตุผลที่เทสต์มีสองข้อคู่กัน — ข้อหนึ่งใช้ −= assert ว่าค่าลด อีกข้อใช้ += assert ว่าค่าเพิ่ม · ถ้าเขียนผิดเครื่องหมาย ข้อที่สองจะเป็นข้อที่ยังผ่านอยู่

สิ่งที่วัดแล้วพบว่าคิดผิด

อาการ: 4-4-1 ไม่ลู่เข้า แต่ 8-8-1 ลู่ → ข้อสรุปตอนนั้นคือ “network เล็กเกินไป”

ที่ lr = 0.01 — network ใหญ่กว่าทนต่อ lr ที่เล็กเกินไปได้ดีกว่า (parameter เยอะกว่า แต่ละก้าวจึงขยับผลรวมได้มากกว่า) ทำให้ ดูเหมือน ขนาดช่วยแก้ ทั้งที่จริงมันแค่กลบอาการของ lr ที่ยังไม่เหมาะ

บทเรียนเรื่องวิธีทดลอง

เปลี่ยนสองอย่างพร้อมกัน แล้วผลดีขึ้น — ยังไม่รู้ว่าอันไหนช่วย
เปลี่ยน 4-4-1 เป็น 8-8-1 คือเปลี่ยนขนาด และชุด weight เริ่มต้นพร้อมกัน · วิธีแยกคือ รันซ้ำหลายรอบด้วยค่าสุ่มต่างกัน แล้วนับว่ากี่รอบที่สำเร็จ
เป็นทักษะเดียวกับ mutation testing — เปลี่ยนทีละอย่าง แล้วดูว่าเกิดอะไร

ลำดับที่ควรปรับ

1. lrผลแรงที่สุด · ปรับด้วย ×10 ÷10 ไม่ใช่ทีละนิด
2. จำนวนรอบถูกที่สุด
3. ขนาด layerปรับทีหลัง เมื่อสองอันบนหมดทางแล้ว

กับดักที่ซ่อนอยู่ในเป้าหมาย

tanh ให้ค่าในช่วง เปิด (−1, 1) — ไปถึง ±1 ไม่ได้เลย ต่อให้ weight ใหญ่แค่ไหน

อยากได้ tanh(z)ต้องใช้ ztanh'(z)
0.91.471.90e-01
0.992.651.99e-02
0.9993.802.00e-03
1.0∞0

ตั้งเป้าไว้ที่ ±1 = สั่งให้ optimizer ดัน weight ขึ้นเรื่อยๆ ไม่มีที่สิ้นสุด และยิ่งดัน ยิ่งเข้าเขตอิ่มตัวที่ tanh' เข้าใกล้ศูนย์ — ยิ่งเรียนช้าลงเรื่อยๆ

loss จึงมีพื้นที่ไม่ใช่ศูนย์ ทั้งที่เครือข่ายไม่ได้ผิดอะไร — ใช้ ±0.9 แทน จะเห็น loss ลงได้ลึกกว่าและเร็วกว่า

สิ่งที่เก็บไว้ อาจเก็บไปทั้งกราฟ

loss_history.append(loss)          # เก็บทั้ง Value → ทั้งกราฟยังมีชีวิตอยู่
loss_history.append(loss.data)     # เก็บแค่ตัวเลข → กราฟถูกทิ้งได้

Value ตัวหนึ่งอ้างถึง _prev ของมัน ซึ่งอ้างถึง _prev ต่อไปเรื่อยๆ — เก็บ loss ไว้ตัวเดียว = เก็บ node ทุกตัวของ forward pass รอบนั้นไว้ทั้งหมด

100 รอบ × ~340 node = สามหมื่นกว่าก้อนที่ปล่อยทิ้งไม่ได้ · ตอนนี้ยังไม่เจ็บ แต่ ใน PyTorch นี่คือ memory leak คลาสสิกที่สุด — total += loss แทน total += loss.item() ทำให้ VRAM เต็มกลางคัน
