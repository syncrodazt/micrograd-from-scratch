สามบรรทัดที่ปิดเฟส 1

หลังจากมี _backward ครบและมี topological order แล้ว backward() เหลืองานแค่สามอย่าง: ประกาศปลายทาง → หาลำดับ → ไล่เรียก ไม่มีคณิตศาสตร์ใหม่เลยแม้แต่บรรทัดเดียว

จุดที่ต้องสังเกต

บรรทัดที่ตั้ง grad ของ root ใช้ = ไม่ใช่ += — ต่างจากทุกที่ในเอนจิน เพราะมันคือเมล็ดเริ่มต้น ไม่ใช่การรับค่าจากใคร (∂root/∂root = 1 เสมอ)

เรียก backward() สองรอบ แล้วเจอบั๊กที่ยังไม่ได้เขียน

ผลการทดลอง: gradient เบิ้ล

เหตุผลอยู่ในโครงสร้างพอดี — backward() รีเซ็ตให้แค่ root ตัวเดียว ส่วน node ที่เหลือทั้งกราฟใช้ += เรียกซ้ำเมื่อไหร่ก็ทับสะสมของเก่าหมด

ทุก training step ต้องเป็น
zero grad ทุกตัว → forward → backward → update weight

คำถามที่น่าสนใจกว่า: ทำไม backward() ไม่ล้างให้เองเลย

ดูเหมือนจะสะดวกกว่า แต่เขาจงใจไม่ทำ — เพราะบางครั้งการสะสมข้าม backward หลายรอบคือสิ่งที่ต้องการจริงๆ เช่นตอน batch ใหญ่เกินหน่วยความจำ ก็ซอยเป็นก้อนเล็กแล้วปล่อยให้ gradient บวกสะสม ก่อนค่อย update ทีเดียว

PyTorch เลือกแบบเดียวกันเป๊ะ — นั่นคือเหตุผลที่ optimizer.zero_grad() เป็นคำสั่งแยกที่ต้องเรียกเอง และเป็นเหตุผลที่การลืมมันคือบั๊กที่คนเจอกันทุกคน
สิ่งที่เจอในเอนจินหน้าเดียวนี้ ไม่ใช่ของเล่น มันคือข้อตกลงเดียวกับของจริง

ทำไมต้อง rebuild ตอนนี้ ไม่รอตามแผนเดิม

แผนเดิมวาง “พิมพ์ engine.py ใหม่จากความจำ” ไว้เฟส 3 — หลังจากใส่ tanh, exp, __pow__, reflected operator เข้าไปหมดแล้ว เลื่อนขึ้นมาทำก่อน ด้วยเหตุผลข้อเดียว:

ตอนนี้เอนจินเล็กที่สุดเท่าที่มันจะเคยเป็น — Value · __add__ · __mul__ · topo · backward
เดือนหน้ามันจะใหญ่ขึ้นสามเท่า และการ rebuild ของที่ใหญ่กว่า ไม่ได้สอนอะไรเพิ่มเลย — มันแค่ใช้เวลานานขึ้น

ที่สำคัญกว่า: rebuild เป็นเทสต์ข้อเดียวในสามข้อที่ยังไม่เคยลอง explain ผ่านไปแล้วตอนเดินเมื่อเช้า debug ผ่านไปแล้วจาก 6 คำถาม การเลื่อนเทสต์ที่ยังไม่เคยสอบออกไปเรื่อยๆ คือการเดาว่าตัวเองผ่าน

เทสต์คือโจทย์ ไม่ใช่การตรวจการบ้าน

ความเข้าใจปกติคือ “เขียนโค้ดเสร็จแล้วค่อยเขียนเทสต์มาตรวจ” แต่รอบนี้ทำกลับกัน — เทสต์มาก่อน แล้วโค้ดตามมาทีหลัง ซึ่งเปลี่ยนบทบาทของมันไปเลย:

เทสต์เขียนทีหลังเทสต์เขียนก่อน
ยืนยันสิ่งที่เขียนไปแล้วนิยามว่าต้องทำอะไรได้
มักเผลอเทสต์ตามที่โค้ดทำไม่รู้จักโค้ดเลย จึงไม่เผลอตามกัน
ตอบว่า “พังไหม”ตอบว่า “ต่อไปทำอะไร”

ไฟล์ tests/test_engine.py จึงเขียนแบบสเปก — บอกว่าต้องทำอะไรได้ ไม่มีคำใบ้ว่าทำยังไงสักที่ ชื่อเทสต์เป็นประโยคเต็ม เพื่อให้ตอนพังมันอ่านเหมือนคำบอกว่าอะไรเสีย ไม่ใช่ป้ายชื่อ

เทสต์ที่จับบั๊กไม่ได้ ก็ไม่ต่างจากไม่มีเทสต์

ก่อนใช้จริง ต้องพิสูจน์ก่อนว่ามันมีเขี้ยว วิธีคือ mutation testing — จงใจใส่บั๊กเข้าไปทีละตัว แล้วดูว่าเทสต์จับได้ไหม

แถวสุดท้ายน่าสนใจที่สุด — พังแค่ข้อเดียว เพราะ _backward เป็น closure ที่จับ self กับ other ไว้เอง ไม่เคยอ่าน _prev เลย gradient จึงยังถูก มีแต่รูปกราฟที่โกหก

ถ้าออกแบบอีกแบบ (เก็บ _op ไว้แล้ว if/elif ตอน backward) บั๊กเดียวกันนี้จะทำให้ gradient ผิดจริง และเงียบ
บั๊กตัวเดียวกัน ร้ายแรงไม่เท่ากัน ขึ้นกับว่าออกแบบไว้ยังไง — closure ทำให้บั๊กนี้กลายเป็น error ที่มองเห็น แทนที่จะเป็นตัวเลขผิดเงียบๆ นั่นคือคุณสมบัติของการออกแบบที่ดี ไม่ใช่เรื่องบังเอิญ

Package กับ import — เรื่องที่ notebook ซ่อนไว้ทั้งหมด

ใน notebook ทุกอย่างอยู่ใน namespace เดียว พอแยกเป็นไฟล์จริงถึงได้เจอว่า Python หาโมดูลเจอได้ยังไง 

micrograd/
    __init__.py     ← มีไฟล์นี้ โฟลเดอร์ถึงเป็น "package"
    engine.py
    topo.py
tests/
    test_engine.py
ที่พังตอนแรก

from topo import topo ไม่ผ่าน เพราะโฟลเดอร์ที่อยู่บน sys.path คือ repo root ไม่ใช่ micrograd/
Python เห็น micrograd เป็น package แต่ไม่เห็น topo เป็นโมดูลระดับบนสุด 

from micrograd.topo import topo    # absolute — อ่านแล้วรู้ว่ามาจากไหน
from .topo import topo             # relative — จุดเดียว = "โฟลเดอร์เดียวกับฉัน"

กับดักถัดไปห่างกันสองนาที: circular import

topo.py อยากใส่ type hint root: Value จึง import Value จาก engine.py — แต่ engine.py ก็กำลัง import topo อยู่: 

ImportError: cannot import name 'Value' from partially initialized
module 'micrograd.engine' (most likely due to a circular import)

คำว่า partially initialized คือคำใบ้ทั้งหมด — โมดูลยังรันไม่จบ ชื่อจึงยังไม่ครบ

ทางออกได้ / เสีย
ตัด type hint ทิ้งง่ายสุด · เสีย type hint
ใส่เป็น string "Value"ไม่ import จริงตอนรัน · ยังได้ hint
if TYPE_CHECKING:วิธีมาตรฐาน — import เฉพาะตอน type checker อ่าน
ยุบกลับเป็นไฟล์เดียวไม่มีปัญหานี้เลย · เทสต์แยกไม่ได้

เกร็ดที่ทำให้เทสต์ยังทำงาน: ชื่อที่ import เข้ามาในโมดูล นับเป็น attribute ของโมดูลนั้นด้วย — engine.py เขียน from micrograd.topo import topo แล้ว micrograd.engine.topo ก็มีอยู่จริง เทสต์จึงหาเจอโดยไม่ต้องแก้อะไร

ผลของ rebuild

ผ่านครบ 29 ข้อ และผิดตรงจุดเดียวที่ควรผิด — ลืม reverse

ประโยคที่สำคัญที่สุดของทั้งวัน

“พอมันไม่ได้ plot graph ออกมา บางทีมันไม่เห็นภาพ แต่พอย้อนคิดดูแล้ว เอ้ยมันต้อง reverse”

นี่คือความต่างระหว่าง “จำได้” กับ “รู้” — ไม่มีรูป ไม่มีโน้ต ก็ยังไล่กลับไปหา invariant แล้ว derive คำตอบออกมาใหม่ได้ ถ้าเป็นการท่องจำ พอไม่มีรูปก็จบ

และ reverse คือขั้นเดียวในเอนจินที่ไม่มีเหตุผลเชิงสัญชาตญาณรองรับ — ทุกบรรทัดอื่น derive จากแคลคูลัสหรือจากกฎ “พ่อมาก่อนลูก” ได้ตรงๆ ส่วน reverse เป็นผลข้างเคียงของการเลือกบันทึก node ที่ท้ายลูป จึงเป็นจุดที่ความจำหลุดง่ายที่สุด — และเป็นจุดที่หลุดจริง
