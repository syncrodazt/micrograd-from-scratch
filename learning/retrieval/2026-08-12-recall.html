“การที่เราออกไปตอนเช้า มันเป็นการทบทวนที่ดี แล้วมันฟิตอยู่ในสมอง พอใน session ครั้งถัดไป เราก็เขียนโค้ดออกมาได้เลย ถ้าเกิดเราไม่มี session แบบนี้ — session แบบ recall หรือแบบพูดทบทวนตัวเอง — ระดับความเข้าใจ ระดับ recall ของเราจะไม่ดีขนาดนี้”

หน้านี้เก็บสภาพความเข้าใจ ณ วันที่ 12 ส.ค. ไว้ตรงๆ รวมทั้งจุดที่พูดวน ที่เดาผิด และที่ยังตอบไม่ได้ — ตรวจแล้วที่ หน้า review

โจทย์ที่ตั้งไว้ก่อนออกเดิน

ช่วงทำอะไร
1 · 0–8 นาทีเล่าทั้งเส้นออกเสียง ตั้งแต่ Value(2.0) จนถึง MLP ที่เทรนได้
2 · 8–15 นาทีเขียนในหัวทีละบรรทัด — Neuron, Layer.parameters(), MLP.__init__

บวกคำถามค้างจากเมื่อคืน: ทำไมเซ็ตศูนย์เฉพาะ parameter ไม่ต้องเซ็ตตัวกลาง 85 ก้อน

คำถามค้าง — ทำไมล้างเฉพาะ parameter

ไอตัว 84 ตัวที่นั่นนะ มันก็จะถูกคำนวณใหม่ มันจะเป็นคนละ value คนละ object พองั้น grad มันจะเป็นศูนย์อยู่แล้ว

อีกอย่าง ไม่แน่ใจ คือเราจำเป็นต้องคำนวณ gradient ของพวกนั้นไหม คือเราแค่ต้องการ gradient ของ weight กับ bias เท่านั้น แต่คำตอบคือ เวลาคำนวณ gradient ของลูก เราต้องมี gradient ของพ่อกลับมาทั้งหมด ถ้ามีสอง layer แล้วเราไม่คำนวณ gradient ของ intermediate value ของ layer ที่สอง gradient ของ weight กับ bias ของ layer 1 มันก็คำนวณไม่ได้ เพราะ layer แรกมันอยู่ใต้ parent ที่สอง

ประเด็นคือที่ไม่ต้อง reset เป็นศูนย์ เพราะมันเป็น value ที่สร้างใหม่อยู่แล้ว

ช่วงที่ 1 — เล่าทั้งเส้น

Value เอามาบวกเอามาคูณ มันก็ trace ออกมาเป็น graph แล้ว graph เราเรียก topo ได้ มันจะให้ลำดับว่าต้องไล่ backward ยังไง

Implementation detail ตอน sum เราใส่ argument ที่สองได้ ไม่ต้อง sum(w*x) แล้วค่อย + b — ใส่ b เป็น start ของ sum ได้เลย ไม่รู้ว่าจะเร็วขึ้นแค่ไหน แต่ทำได้

เรื่องที่คิดต่อ สุดท้ายถ้าอยากให้เหมือน PyTorch เราอยากเลือก activation function ได้ ตอนนี้เราฝังไปเลยว่าเป็น tanh แต่ต่อไปอาจจะให้ input เป็น activation function ก็คือเลือกได้ว่าจะ activate ยังไง — tanh, relu

ช่วงที่ 2 — เขียนในหัว

Neuron ตอน implement มันจะมี parameters() ด้วย แล้วก็อย่าลืม __repr__ เวลา print ออกมาจะได้เห็นว่า parameter ของ neuron มีอะไรบ้าง

ตอนแรกไม่รู้ว่า Neuron.parameters() เอาไปใช้ตอนไหน — อ๋อ มันเอาไว้ใช้ตอนสุดท้ายที่ MLP เราอยาก get parameter ของ MLP เราก็เลยต้องไล่ในแต่ละ layer แล้วใช้ neuron.parameters() ถ้าไม่มี Neuron.parameters() ตอนทำ Layer.parameters() กับ MLP.parameters() มันจะลำบาก โอเค เก็ตแล้วว่าทำไมต้องมี

__call__ เราสร้าง def __call__ argument แรกเป็น self argument ที่สองเป็น xs ก็คือตัวเลขที่เอามาใส่ neuron ถ้า n = Neuron(3) เราก็เรียก n([...]) ได้ คือเราเรียก class เป็นฟังก์ชันได้

เรื่องที่คิดต่อ ไอ้นี่เจ๋ง ถ้าเรียนอันนี้เปล่าๆ ไม่ได้อยู่ใน context ของ micrograd เราก็จะไม่รู้ว่ามันเอาไปใช้อะไร แต่พอเรียน micrograd แล้วลองใช้ฟีเจอร์ของ Python จริงๆ มันทำให้รู้ว่าฟีเจอร์อย่างนี้ใช้จริงยังไง อย่างเมื่อวานเรื่องดอกจันอันเดียวกับสองอัน — ดอกจันเดียวคลี่เป็น tuple สองดอกจันคือ keyword arguments ได้เป็น dictionary ที่มี field a=1 b=2 (dictionary field มันเรียกว่าอะไรนะ name-value pair ป่ะ) เป็นฟีเจอร์ของ Python ที่เราจำไม่ได้สักที แต่พอมาใช้จริงกับ micrograd แล้วรู้แล้วว่าใช้ยังไง

MLP input แรกคือจำนวน input ของทั้ง network ตัวที่สองเป็น list ว่าแต่ละ layer มีกี่ neuron สมมติ MLP(3, [4, 4, 1]) — layer 1 มี 4 neuron, layer 2 มี 4, layer 3 มี 1

Layer รับสองอย่าง: มี input กี่ตัว และมีกี่ neuron เพราะงั้น layer แรกคือ (3, 4) — 3 input, 4 neuron layer ต่อไป input ของมันคือ 4 เพราะ layer แรกมี 4 neuron → (4, 4) layer สาม input คือจำนวน output ของ layer สอง = 4 → (4, 1)

จะเห็นว่า column แรกคือ 3, 4, 4 และ column ที่สองคือ 4, 4, 1 เพราะงั้นที่ zip ก็คือ zip [3, 4, 4, 1] กับ [4, 4, 1] เราเพิ่ม input แรกเข้าไปข้างหน้า แล้วจับคู่กัน

output ของ MLP ต่างจาก layer ตรงที่ output ของ MLP คือ output ของ layer สุดท้าย เอา input ไป forward ใน layer แรก ได้ output มา เอาไปใส่ layer สอง เอา output ของ layer สองไปใส่ layer สาม ไปเรื่อยๆ จนถึง layer สุดท้าย

จุดที่ยังไม่เก็ต ตอนที่มี list ของ list แล้วอยากจะ flatten ให้เป็น list เดียว unpacking ด้วยดอกจันมันใช้ไม่ได้ใน list comprehension — ตรงนั้นยังไม่เก็ตว่าทำไม เกี่ยวกับ generator สักอย่าง

ช่วงที่ 3 — อะไรพังถ้า…

ข้อ 1 · weight = 0 ทุกตัว

ตอน run forward pass ทุกอย่างก็จะเป็น 0 หมด output เป็น 0 เข้า tanh — tanh(0) = 0 ทุกอย่างเป็น 0 แล้วไปคำนวณ loss ได้ loss มา คำนวณ gradient — gradient ของ loss เป็น 1 คือ intermediate value เป็นศูนย์หมดเลย

เพราะงั้นตอน update gradient อย่าง w*x + b ตอนหา gradient ของ w มันเอา gradient ของพ่อคูณกับ x ใช่ไหม แล้วถ้า x เป็นศูนย์ gradient ของ w ก็เป็นศูนย์ แล้วพอ gradient เป็นศูนย์มันก็ทำอะไรไม่ได้ เพราะไม่รู้จะปรับยังไง

(loss คือ (y_pred − y_true)² ใช่ไหม)

ข้อ 2 · weight = ±20

weight มันจะไม่ได้อยู่ช่วง −1 ถึง 1 แล้ว มันอยู่ช่วง −20 ถึง 20 ถ้ามี input 3 ตัวก็มี weight 4 ตัว (w 3 ตัว + b 1 ตัว) weight 4 ตัวช่วง −20 ถึง 20 ค่าที่ได้ก็คือ −80 ถึง 80

พอใส่เข้าไปใน tanh — tanh(80) มันแทบจะเป็น 1 แล้ว ตอนทำ backprop tanh' คือ 1 − tanh² ≈ 0 พอ gradient เข้าใกล้ 0 แล้วเอาไปคูณต่อ ก็ยิ่งน้อยเข้าไปใหญ่ นี่คือปัญหา vanishing gradient

ข้อ 3 · input ไม่ครบ

มันจะคำนวณผิด ต้องให้มันขึ้น error ว่าจำนวน input จริงกับจำนวน input ของ neuron ต้องเท่ากัน โดยใช้ strict ใน zip

ข้อ 4 · 5 · 6

ข้อ 4 ไม่ค่อยเข้าใจคำถาม p คืออะไร parameter ป่ะ

ข้อ 5 ยังไม่ได้ตอบ

ข้อ 6 ยังไม่ได้ตอบ · จำได้ว่า lr คือ learning rate

ข้อ 7 · ลืม zero_grad

ประเด็นคือเราเทรนด้วย data ใหม่ พอเทรนด้วย data ใหม่เราก็ได้ loss อันใหม่ เป้าหมายคือเราอยากปรับ network ให้ minimize loss เมื่อเทียบกับ input/output ชุดนั้น สิ่งที่เราจะปรับในแต่ละครั้งมันต้องขึ้นกับข้อมูลใหม่ ไม่ใช่ข้อมูลเก่า การที่เราไม่ reset gradient มันเหมือนว่าเรายังจำข้อมูลเก่าอยู่ เพราะ gradient มันยังเป็นของข้อมูลเก่า

เปรียบเทียบกับการเดิน — แต่ละชุดข้อมูลบอกทิศทางมา ข้อมูลเก่าบอกว่าให้ตรงไป ข้อมูลใหม่บอกว่าให้ไปทางขวา ถ้าไม่เซ็ตเป็นศูนย์ พอบอกให้ไปขวา เราก็ยังเดินไปข้างหน้าอยู่ด้วย มันจะกลายเป็นเดินเฉียงๆ

คำถามที่โผล่ขึ้นมาเอง อันนี้เหรอที่เขาเรียกว่า momentum คือการคงทิศทางของข้อมูลก่อนหน้าไว้ เพราะมันก็ยังเป็นข้อมูลที่มีคุณค่าอยู่ ถ้าไป convert gradient ใหม่หมดมันเหมือนเสียข้อมูลไปเปล่าๆ และเหมือนจะก้าวไปข้างหน้าได้เร็วกว่าด้วย ถ้า gradient อันแรก represent ความเป็นจริง การเดินไปทิศทางนั้นก็ถูกแล้ว ถ้าเราแค่ปรับทิศทางเดิมด้วย gradient อันใหม่ — อันนั้นคือ momentum ใช่ไหม
