# 🔴 สามจุดที่ต้องแก้

## 1. `id` vs `hash` — ผิดเรื่องพฤติกรรมจริงของ Python

นายพูดว่า:

> *"ถ้าเรามี Value ที่เป็น 2 สองตัวคนละตัวแปร — hash มันเหมือนกัน แต่ ID ไม่เหมือนกัน"*

ผมรันเทสต์กับ `Value` แบบที่นายมีตอนนี้:

```
a = Value(2.0); b = Value(2.0)

a.data == b.data    : True
id(a)  == id(b)     : False
hash(a) == hash(b)  : False   ← นายคิดว่า True
a == b              : False
```

**hash ต่างกันด้วย** เพราะตอนนี้ `Value` ยังไม่มี `__eq__` Python จึงถือว่า *"เท่ากัน = เป็นก้อนเดียวกัน"* แล้วคำนวณ hash จาก id ตรงๆ — hash กับ id จึงพูดเรื่องเดียวกันอยู่ตอนนี้

**สิ่งที่นายอธิบายจะเป็นจริงก็ต่อเมื่อเขียน `__eq__` เอง** — ผมลองให้ดู:

```
class Value2:  def __eq__(self, o): return self.data == o.data

hash(c) == hash(d)  : True
len({c, d})         : 1     ← ยุบเหลือ node เดียว! กราฟพังทันที
```

> **ความเข้าใจเชิงแนวคิดของนายถูก** (id = ตัวตน, hash = ความเท่ากัน) — ผิดแค่ว่า *ตอนนี้* Python ยังไม่ได้แยกสองอย่างนี้ให้ เพราะเรายังไม่ได้บอกมันว่า "เท่ากัน" แปลว่าอะไร

## 2. Newton's method ≠ gradient descent

นายบอกว่า *"มันเหมือนทฤษฎีของนิวตัน Newton method"* — **คนละอย่าง** และนายเป็นวิศวกร control ควรแยกให้ขาด:

| | สูตรอัปเดต | ใช้อนุพันธ์อันดับ |
|---|---|---|
| **Gradient descent** | `x ← x − lr · f′(x)` | **หนึ่ง** |
| **Newton's method** | `x ← x − f′(x) / f″(x)` | **สอง** (Hessian) |

Newton ลู่เข้าเร็วกว่ามาก แต่ต้องคำนวณ Hessian ซึ่งสำหรับพารามิเตอร์พันล้านตัวคือเมทริกซ์ขนาดพันล้าน × พันล้าน — **เป็นไปไม่ได้** นี่คือเหตุผลที่ deep learning ใช้ first-order เกือบทั้งหมด

ที่นายอธิบาย (*"หาความชัน แล้ว shift ไปทางความชันนิดหน่อย"*) คือ **gradient descent** ถูกแล้ว แค่เรียกชื่อผิด

## 3. k-means ไม่ใช่ classifier — และตอบคำถามที่นายฝากไว้

นายถามว่า *"วิธี ML ธรรมดาสำหรับจุดใน 2D คืออะไร จำไม่ได้ K-means?"*

**k-means กับ k-NN เป็นคนละอย่าง** และคนสับสนกันเยอะเพราะชื่อคล้าย:

| | ทำอะไร | มี label ไหม |
|---|---|---|
| **k-means** | จับกลุ่มจุดที่คล้ายกัน (clustering) | ❌ ไม่มี — unsupervised |
| **k-NN** | ดู k เพื่อนบ้านที่ใกล้ที่สุด แล้วโหวต | ✅ มี — supervised |

**วิธีคลาสสิกสำหรับ binary classification บนจุด 2D:**
logistic regression · k-NN · SVM · decision tree

**และนี่คือคำตอบที่แท้จริงของ "ทำไมต้องใช้ NN":**

> วิธีคลาสสิก **คนต้องเป็นคนเลือกรูปทรงของเส้นแบ่ง** — logistic regression วาดเส้นตรงได้อย่างเดียว ถ้าอยากได้เส้นโค้งต้องนั่งคิด feature เอง (`x²`, `xy`, ...) SVM ต้องเลือก kernel
>
> **Neural net เรียนรูปทรงนั้นเอง** จากข้อมูล ไม่ต้องมีใครบอก — ยิ่งปัญหาซับซ้อน (ภาพ เสียง ภาษา) ยิ่งไม่มีมนุษย์คนไหนออกแบบ feature ได้ทัน นั่นแหละคือเหตุผล

# 🧩 Closure — สอนใหม่ด้วยมุมอื่น

นายบอกว่ายังไม่ get และผมว่าคำอธิบายเดิมของผมยังไม่ตรงจุด ลองมุมนี้

## สิ่งที่นายเข้าใจถูกแล้ว

> *"มันคล้าย global variable แต่เป็น global ใน context ของ function"*

**ใกล้มาก** แต่พลาดคุณสมบัติที่สำคัญที่สุดไป — และคุณสมบัตินั้นคือเหตุผลที่มันมีอยู่

## คุณสมบัติที่ยังไม่เห็น: **ตัวแปรมีชีวิตอยู่ต่อ หลังฟังก์ชันแม่จบไปแล้ว**

ปกติตัวแปร local **ตายทันที**ที่ฟังก์ชันจบ แต่ลองรันอันนี้:

```python
def make_counter():
    n = 0
    def bump():
        nonlocal n
        n += 1
        return n
    return bump          # ← make_counter จบตรงนี้ n ควรจะตายแล้ว

c1 = make_counter()
c2 = make_counter()

print(c1(), c1(), c1())   # 1 2 3
print(c2())               # 1   ← ไม่ใช่ 4
```

**สังเกตสองอย่าง:**

1. `make_counter` **จบไปนานแล้ว** แต่ `c1()` ยังใช้ `n` ได้ → `n` ไม่ตาย เพราะ `bump` ยังถือกล่องมันอยู่
2. `c1` กับ `c2` มี `n` **คนละตัว** → **นี่คือจุดที่ต่างจาก global โดยสิ้นเชิง**

| | global | closure |
|---|---|---|
| มีกี่กล่อง | **หนึ่งกล่องตลอดกาล** | **กล่องใหม่ทุกครั้งที่เรียกฟังก์ชันแม่** |
| ใครแตะได้ | ทุกคนในโปรแกรม | เฉพาะฟังก์ชันที่ถูกสร้างพร้อมกัน |

**และนี่คือเหตุผลที่ `trace()` ของนายใช้ closure ถูกแล้ว** — เรียก `trace(d)` สองครั้งได้ตะกร้าคนละใบ ไม่ปนกัน ถ้าใช้ global จริง ครั้งที่สองจะเจอ node เก่าค้างอยู่

## ทำไมชื่อ "closure"

นายเดาว่ามาจาก *"close global variable"* — เกือบ แต่มาจากอีกทาง:

- `bump` ใช้ชื่อ `n` แต่ไม่ได้นิยามเอง ไม่ได้รับมาเป็น argument → `n` เรียกว่า **free variable** (ตัวแปรลอย)
- ฟังก์ชันที่มีตัวแปรลอยเรียกว่า **"เปิด" (open)** — เอาไปรันเดี่ยวๆ ไม่ได้ ไม่รู้ว่า `n` คืออะไร
- Python **"ปิด" (close over)** มันให้ โดยแนบกล่องติดตัวไป → กลายเป็น **closure**

## ทำไมต้องรู้ตอนนี้ — payoff อยู่พรุ่งนี้

`_backward` ของแต่ละ operation จะเป็น closure ที่ **แบก `self`, `other`, `out` ติดตัวไป หลังจาก `__add__` return ไปแล้ว**

พอถึงเวลา backward — `__add__` จบไปนานแล้ว แต่ closure ยังจำได้ว่าตัวเองเกิดจากใคร **นี่คือกลไกที่ทำให้ backward pass เป็นไปได้เลย** ถ้าไม่มี closure จะต้องเก็บข้อมูลพวกนี้ไว้เองด้วยมือทุก node

> **ลองรัน `make_counter` ข้างบนจริงๆ นะ 30 วินาที** — เห็น `1 2 3` แล้ว `1` ด้วยตาตัวเอง จะ get ทันที

# 🔤 Dunder — สั้นๆ

`__add__`, `__repr__`, `__init__` — "dunder" = **d**ouble **under**score

**แนวคิดเดียวที่ต้องจำ: นายไม่ได้เรียกมัน — นายเขียนไว้ แล้ว Python เรียกให้**

```
a + b      →  Python เรียก a.__add__(b)
print(a)   →  Python เรียก a.__repr__()
len(a)     →  Python เรียก a.__len__()
```

มันคือ **จุดเสียบปลั๊ก (hook)** ที่ Python เปิดไว้ให้ class ของเราเข้าไปแทรกพฤติกรรมของ syntax พื้นฐาน

**ทำไมชื่ออัปลักษณ์แบบนั้น** — เพื่อไม่ให้ชนกับชื่อเมธอดปกติที่คนตั้งเอง ไม่มีใครบังเอิญตั้งชื่อเมธอดว่า `__add__`

- ทำไม numerical gradient ใช้ไม่ได้ — **2 เหตุผลครบ** และนายเสริมเองว่า "โมเดลจริงมีพันล้านตัวแปร"
- DAG vs tree + `x*y + x` — ครบ
- `git add` เก็บสำเนา ณ วินาทีนั้น — ครบ
- Value เก็บอะไร — ครบ (data, `_prev`, `_op`, grad)
- Loss = ผลต่างระหว่าง y ที่อยากได้กับ y ที่ได้ **ยุบเป็นตัวเลขตัวเดียว** ← ข้อ "ตัวเลขตัวเดียว" สำคัญมากและนายพูดเอง
- Learning rate + อุปมายักษ์ก้าวข้ามภูเขา — ถูกและอธิบายเก่ง

**สองอันนี้ผมประทับใจเป็นพิเศษ:**

1. *"เราต้อง forward pass ก่อน เพราะตอนหา gradient เราต้องรู้ค่าแต่ละตัวใน computation graph"* — **นี่คือประเด็นที่ละเอียดและคนพลาดกันเยอะ** backward ต้องใช้ค่าจาก forward (เช่น gradient ของ `a` ใน `a*b` ต้องใช้ค่าของ `b`) นายเห็นเองโดยไม่มีใครบอก

2. อุปมาตีเทนนิส — *"ถ้าไม่รู้ว่ามันแตกต่างทางไหน เราก็ไม่รู้จะปรับไปทางไหน ก็ต้องสุ่มมั่วๆ"* — นั่นคือคำตอบว่า**ทำไมต้องมี gradient แทนที่จะสุ่ม** อธิบายได้ดีกว่าตำราหลายเล่ม

# 📌 ตอบคำถามที่นายฝากไว้ระหว่างทาง

**"ทำไมเรียกว่า Loss Function?"**
มาจาก statistical decision theory — loss คือ "ราคาที่ต้องจ่ายเมื่อทายผิด" ชื่ออื่นที่ใช้แทนกันได้: cost function, objective function, error function
(และนายพูดถูกว่า minimize/maximize เป็นแค่เรื่องเครื่องหมาย — ถ้ากลับเครื่องหมายจะเรียกว่า *utility* หรือ *reward* แล้ว maximize แทน ซึ่งคือสิ่งที่ RL ทำ)

**"PyTorch ใช้ class ชื่อ Value ไหม?"**
ไม่ — PyTorch ใช้ **`Tensor`** และเก็บข้อมูลกราฟไว้ที่ `.grad_fn` (≈ `_op` + `_prev` รวมกัน), `.grad` (= `grad`), `.requires_grad` ชื่อ `Value` เป็นของ micrograd โดยเฉพาะ แต่**แนวคิดเหมือนกันเป๊ะ** — micrograd คือ PyTorch ที่ถอด tensor ออกเหลือ scalar

# ⚠️ สิ่งที่นายไม่ได้พูดถึงเลย

ไม่ใช่ว่าตอบผิด — แต่**หายไปจากภาพ** ซึ่งบอกว่ายังไม่อยู่ในหัว:

1. **Activation function / nonlinearity** ← ช่องว่างใหญ่ที่สุด
   นายอธิบาย neuron ว่า `w·x + b` แล้วจบ **แต่ถ้ามีแค่นั้น การซ้อน layer กี่ชั้นก็ยุบเหลือสมการเส้นตรงเดียว** — เครือข่าย 100 ชั้นจะเก่งเท่า logistic regression เป๊ะ นี่คือเหตุผลที่ `tanh` ต้องมี (ข้อ 7 ในแผนวันนี้)
2. **ทำไมลำดับถึงสำคัญตอน backward** — นายไม่ได้แตะเรื่อง topological sort เลย
3. `__repr__` และเหตุผลที่ต้องมี
4. Reflected operator (`__rmul__`) — จะบล็อกนายตอน Neuron
5. Mutable default argument
6. **gradient ของ node ที่มีลูกหลายตัวต้องทำยังไง** — นายบอกว่า "ซ้ำแล้วจะมีปัญหาตอนคำนวณ gradient" ถูก แต่ยังไม่ได้บอกว่า*ปัญหาอะไร* — อันนี้ตั้งใจไม่เฉลย เก็บไว้เจอเอง

# 🎯 อัปเกรดหนึ่งอย่างสำหรับสมองสาย control ของนาย

นาย map ไปที่ **control** — *"เรามี system เราอยากให้ output เป็นอย่างที่ต้องการ"* ใกล้แล้วแต่ยังไม่ตรง:

| | ปรับอะไร | อะไรคงที่ |
|---|---|---|
| **Control** | **input** (สัญญาณควบคุม) | plant คงที่ |
| **Training NN** | **พารามิเตอร์ของ plant เอง** | input–output data คงที่ |

การเทรน NN ไม่ใช่ control — **มันคือ system identification / parameter estimation** นายมี input–output data ชุดหนึ่ง แล้วปรับ*ตัวแบบ*ให้ fit ข้อมูลนั้น

นายพูดเองระหว่างอัดว่า *"อ๋อ input เรา fix แล้ว เราปรับ weight"* — **นายไปถึงข้อสรุปนี้เองแล้ว** ผมแค่ให้ชื่อเรียกที่ถูกต้องกับมัน

(ส่วน backprop เอง ≈ **adjoint / costate equation** ที่วิ่งย้อนเวลากลับ — อันนั้นตรงเป๊ะ)
