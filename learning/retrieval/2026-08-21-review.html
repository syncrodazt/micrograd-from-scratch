ข้อที่โจทย์ผิดเอง

เออเมื่อกี้พูดผิดว่ะ … แล้วถ้าพี่บอกทำสี่อย่างนี่มันคืออะไรนะ เพราะตอนเราคิดตอนนี้มันมีแค่สองอย่างป่ะ

โจทย์ที่ผมตั้งว่า “backward() ทำ 4 อย่าง” ผิด — ในโค้ดที่เขียนเองมี 3 บรรทัด 3 อย่าง: 

def backward(self) -> None:
    self.grad = 1.0          1. ตั้ง grad ของ root
    order = topo(self)       2. เรียงลำดับ
    for n in order:          3. เรียก _backward ตามลำดับนั้น
        n._backward()

ที่แก้ตัวเองนั้นถูก 100% — backward() คำนวณ gradient อย่างเดียว · การอัปเดต parameter กับ zero_grad อยู่ใน training loop ไม่ใช่ใน backward()

และที่นับได้ “สองอย่าง” ก็เกือบครบ — ที่ขาดคือ topo(self) ซึ่งเป็นขั้นแยกจริงๆ ส่วน reversed() ไม่ได้อยู่ใน backward() เพราะย้ายไปไว้ใน topo() แล้ว — การออกแบบของตัวเอง ต่างจากของ Karpathy ตรงนี้

Value — ได้ 4 จาก 6

fieldตอบได้?มีไว้ทำไม
data✅ค่าของ node
grad✅อนุพันธ์ของ loss เทียบกับ node นี้
_prev✅ใช้เดินกราฟตอน topological sort
_op✅ (บอกเองว่าใช้แค่ตอนวาดกราฟ — ถูก)ป้ายกำกับสำหรับ graphviz
_backward❌ ไม่ได้นับเป็น fieldclosure ที่เก็บวิธีกระจาย gradient ของ node นั้นโดยเฉพาะ
label❌ชื่อที่ตั้งเองสำหรับอ่านกราฟ

_backward เป็นตัวที่น่าสนใจที่สุด — พูดถึงมันตลอดทั้งสามข้อ แต่ไม่ได้นับว่ามันคือ field ที่เก็บอยู่บน object ทั้งที่มันคือสิ่งที่ทำให้ _op ไม่ต้องถูกอ่านตอน backward เลย

_prev เป็น list หรือ set — ที่ลังเลไว้

โค้ดที่เขียนเองใช้ list (self._prev = list(_prev)) และเหตุผลที่ให้ไว้ก็เป็นเหตุผลที่ถูก

ที่ต้องระวังคือคำว่า “ลำดับไม่สำคัญ” — สำหรับความถูกต้องของ gradient ไม่สำคัญจริง เพราะ _backward เป็น closure ที่จับ self กับ other ไว้แล้ว และไม่เคยอ่าน _prev เลย
แต่ set จะยุบตัวซ้ำ — x + x จะเหลือ _prev ตัวเดียว ทำให้กราฟที่วาดออกมาโกหก ทั้งที่ตัวเลข gradient ยังถูก

⭐ คำถามที่ตั้งเองระหว่างวิ่ง — วัดแล้ว และเจอของจริง

เฮ้ยมันจะมีปัญหาหรือเปล่าเรายังไม่รู้ … closure มันฝังข้อมูลใส่ในฟังก์ชัน มันเปลือง memory แค่ไหน … มันไปเก็บข้อมูลไว้ไหน เก็บใน RAM หรือยังไง

รันวัดจริงบน engine ที่เขียนเอง:

sizeof(Value instance dict) : 280 bytes
sizeof(_backward function)  : 160 bytes
free vars captured          : ('other', 'self', 't')
cells                       : 3

ราคาของ closure คือประมาณ 160 ไบต์ต่อ node บวก cell อีก 3 ตัว — ไม่ได้ copy ข้อมูล แค่ถือการอ้างอิง ไปยัง object เดิม ซึ่ง _prev ก็ถืออยู่แล้วอยู่ดี

แต่มีของที่ไม่ได้คิดถึง และมันสำคัญกว่า

does the closure capture t itself?  True
reference cycle

t._backward เป็น closure ที่จับ t ไว้ — t ชี้ไป _backward และ _backward ชี้กลับมาที่ t
แปลว่าตัวนับ reference ของ Python ปล่อย t ทิ้งเองไม่ได้ ต้องรอ cycle collector มาเก็บ

วัดโดยทิ้ง reference สุดท้ายของกราฟ แล้วดูว่ามันตายทันทีไหม:

root still alive after refcount drop?  True     ← ยังไม่ตาย
freed only by the cycle collector?     True     ← ตายตอน gc.collect()
objects collected                      23

คำถามที่ตั้งเองถูกทาง — มีต้นทุนจริง แต่ไม่ใช่ที่คิด · ไม่ใช่ “เปลือง RAM เพราะ copy ข้อมูล” แต่เป็น “node ตายช้ากว่าที่ควร เพราะเป็นวงกลม”

ต่อยอดจากที่เคยวัดไว้ใน Lesson 10: เทรน 100 รอบสร้างทิ้งราว 34,000 ก้อน — ทั้ง 34,000 ก้อนนั้นต้องรอ cycle collector ไม่มีก้อนไหนถูกปล่อยทันที · ที่สเกลนี้ยังไม่เจ็บ แต่เป็นเหตุผลหนึ่งที่ PyTorch ไม่เก็บ backward function ไว้บน tensor แบบนี้

parameters() — “ไม่คืนอะไร” คือคำตอบที่นึกไม่ออก

ที่ลงเอยว่าต้องคืน Value ทั้ง object ไม่ใช่ .data ถูก และเหตุผลก็ถูก: ถ้าคืนแค่ตัวเลข การเขียน p.data -= lr * p.grad จะไปตกที่ก้อนที่ network ไม่ได้อ่าน

ส่วนที่นึกไม่ออก

parameters() ไม่คืน “ตัวกลาง” — Value ที่เกิดจาก w*x, ผลบวก, และ tanh
วัดไว้แล้วใน Lesson 10: MLP(3,[4,4,1]) forward pass เดียวสร้าง 85 ก้อน แต่ parameters() คืนแค่ 41

เส้นแบ่งคือ “อะไรอยู่ข้ามรอบ” — parameter อยู่ต่อ ตัวกลางตายทุกรอบ และนั่นคือเหตุผลเดียวกับที่ zero_grad ล้างแค่ parameter

zero_grad — ถูกตอนกลาง แล้วหลุดตอนท้าย

ตอนกลาง“อย่าลืม Set Gradient เป็น 0 ของทุก Parameter” — ✅ ถูก
ตอนท้าย“ขั้นที่ 0 คือ Preprocessing Input Data เหรอ? Normalization?” — ❌

ขั้นที่ 0 คือ zero_grad ตัวที่พูดถูกไปแล้วเมื่อครู่ — ไม่ใช่ normalization · เงื่อนไขจริงคือมันต้องอยู่ระหว่าง backward() สองครั้ง จะวางต้นรอบหรือท้ายรอบก็ได้

น่าสังเกตว่านี่คือบั๊กที่เจอเองกับมือเมื่อ 12 ส.ค. และอธิบายได้ดีมากตอนนั้น — 9 วันผ่านไปแล้วชื่อของมันหลุด ทั้งที่กลไกยังจำได้ · ข้อนี้ต้องอยู่ในรอบซ้อมก่อน 26 ส.ค.

เส้นฐานที่หนึ่งนับอะไรได้อะไร เล็กเส้นฐานคือเท่าไร ก็คือนับ Bigram ตรงๆ

ตอบว่าทำยังไงได้ แต่ไม่ได้ตัวเลข · เลขนี้คือสิ่งที่ทำให้เฟส 6 ทั้งเฟสวัดผลได้:

ถ้าเขียน bigram.py แล้วได้เลขอื่น แปลว่ามีบั๊ก — เป็นเลขเดียวในเฟส 6 ที่มีเฉลยล่วงหน้า

one_hot(5) @ W — พูดถูกแล้วพูดผิดทับ

ที่พูด
“มันก็เหมือนจับ Row ของไอเวทนั่นน่ะ”✅ ถูกเป๊ะ — และเป็นความก้าวหน้าจากรอบก่อน
“เท่ากับ Probability ของการเกิดแต่ละอักษรหลัง a”❌ นั่นคือหลัง softmax แล้ว

one_hot(5) @ W คือ แถวที่ 5 ของ W ดิบๆ = logit · กว่าจะเป็น probability ต้องผ่าน exp แล้วหารด้วยผลรวมก่อน — ซึ่งเล่าถูกทุกขั้นในย่อหน้าถัดมา แค่พูดข้ามขั้นตอนตรงนี้

และช่วงของ W ไม่ใช่ −1 ถึง 1

ไอเวทของ Neural Network มันคือ -1 ถึง 1

นั่นคือ uniform(-1, 1) ซึ่งเป็นสิ่งที่ Neuron.__init__ ของ micrograd ใช้ · makemore ใช้ torch.randn ซึ่งเป็น gaussian ไม่มีขอบ: 

randn(27,27)   (makemore ใช้)   −2.620 .. 3.752
uniform(-1,1)  (Neuron ใช้)     −0.994 .. 0.998

ค่าที่หลุดออกนอก [-1, 1] ของ randn : 30.9%

ความรู้จากโปรเจกต์เดิมไหลข้ามมาโดยไม่รู้ตัว — เป็นรูปแบบที่จะเจอบ่อยขึ้น ตอนที่ micrograd กับ torch อยู่ใน repo เดียวกัน

⭐ ท่อนที่ดีที่สุด — และตัวเลขที่ยืนยัน

Property ของการเกิด Emma เนี่ยมันก็คือ Property ของแต่ละคู่มาคูณกัน … พอมาคูณกันมันจะเข้าใกล้ศูนย์ … ซึ่งมันไม่สะดวก เราก็เลย Take log พอ Take log แล้วมันก็จะเป็นเหมือนแบบเอา Property มาแค่บวกกัน

นี่คือการ derive cross-entropy ออกมาเองจากศูนย์ ไม่ได้ท่องมา · วัดจริงว่ามัน “เข้าใกล้ศูนย์” เร็วแค่ไหน: 

ava          p = 1.656744e-04
emma         p = 3.478214e-06
olivia       p = 2.483135e-08
alexandria   p = 6.311320e-12

ชื่อยาวขึ้นนิดเดียว ความน่าจะเป็นหายไปเป็นล้านเท่า · แล้วถ้าคูณต่อไปเรื่อยๆ:

คูณ probability เดิมซ้ำๆ → ได้ 0.0 พอดี หลังจาก 408 ตัว

log-likelihood ของทั้ง corpus = −559,873.6

“มันไม่สะดวก” ที่พูดไว้ ในทางตัวเลขคือ “มันเป็นศูนย์พอดี” — ไม่ใช่แค่เล็กจนอ่านยาก แต่ข้อมูลหายไปหมดจริงๆ คูณแค่ 408 ครั้งก็ตันแล้ว ส่วน corpus มี 228,146 ครั้ง

log จึงไม่ใช่แค่ความสะดวก — ถ้าไม่ใช้ ตัวเลขจะเป็น 0.0 แล้ว gradient เป็นศูนย์หมด เทรนไม่ได้เลย

จุดที่พูดสลับ

“Property มันน้อยกว่าหนึ่ง แล้วพอ Take log อะไรของอะไรที่มากกว่าหนึ่งมันก็จะติดลบ” — สลับคำ · log ของอะไรที่น้อยกว่า 1 ถึงจะติดลบ · ประโยคก่อนหน้าและหลังจากนั้นถูกหมด จึงเป็นแค่การพูดสลับ ไม่ใช่ความเข้าใจผิด
