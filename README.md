## The problem: gradients are the bottleneck

<!-- นี่คือของที่นายพูดมาแล้ว แค่ตัดให้สั้นลง
     - train = 3 step วนซ้ำ (พูดใน 2 ประโยค)
     - ทุก step ต้องการ gradient ของ "ทุก" parameter
     - วิธีตรงไปตรงมาคือ finite difference: (f(x+h)-f(x))/h
     - มันพัง 2 ทาง:
         (a) ราคา: N parameter ต้อง N+1 forward pass  ← ใส่ตัวเลขจริงจาก MLP ของเรา
         (b) ความแม่น: error รูปตัว V ← แก้ประโยคเดิมที่บอกว่า h เล็กลงดีขึ้นเสมอ -->

<!-- optional: กราฟ h sweep ตรงนี้ ถ้ารันแล้ว — รูปที่ 2 -->

## The idea: one backward pass, every gradient

<!-- ประโยคเดียวที่ต้องคมที่สุดใน README ทั้งไฟล์
     forward 1 ครั้ง + backward 1 ครั้ง = gradient ครบทุกตัว ไม่ว่าจะมีกี่ parameter -->

## How it actually works

<!-- ช่องที่ใหญ่ที่สุดและตอนนี้ยังว่าง 100%
     คนอ่านตัดสินว่าเราเข้าใจจริงไหมจาก 3 หัวข้อย่อยข้างล่างนี้เท่านั้น -->

### 1. Every value remembers how it was made

<!-- _prev, _op, _backward — graph สร้างตัวเองระหว่าง forward
     ประโยคที่อยากได้: "ไม่มีใครสร้าง graph. forward pass คือการสร้าง graph" -->

### 2. Gradients accumulate

<!-- += ไม่ใช่ =
     ต้องพูดให้ชัดว่านี่คือ chain rule หลายตัวแปร ไม่ใช่ทริค Python
     ใส่ตัวอย่างเล็กที่สุดที่ทำให้ = ผิด (node ใช้ซ้ำ 2 ที่) + ตัวเลขผิดกับตัวเลขถูก -->

### 3. Order is not optional

<!-- invariant 1 ประโยค: node จะ _backward ได้ ต่อเมื่อ grad ของมันครบแล้ว
     ครบเมื่อไหร่ = เมื่อ "พ่อแม่" ทุกตัวทำไปแล้ว
     post-order DFS + reversed ให้ลำดับนั้นเพราะอะไร
